# 작업 로그: 자기 루프 꼬리 호출 제거와 게스트 호스트 스택 확보 (reDMP1 #32)

## 요약

`allegrexrecomp`가 같은 본문(body)이 소유한 진입점으로의 `j` 명령을 `goto` 대신 자기 재귀 호출로 옮겨 호스트 스택이 누적되던 결함을 로컬 패치(`0004-j-owned-target-goto.patch`)로 수정했습니다. 동시에 `tools/lift_audit.py`에 `self_tail_call` 규칙과 교차 함수 꼬리 호출 SCC 집계를 추가했고, `repsp`(`i032-guest-stack`)에서 게스트 스레드별 64 MiB 가상 주소 예약 스택과 OS 스택 최고 사용량 보고를 구현했습니다.

## 변경 내용

1. **로컬 lifter 패치 (`patches/psprecomp/0004-j-owned-target-goto.patch`, `CMakeLists.txt`, `patches/psprecomp/README.md`)**
   * `third_party/psprecomp/tools/allegrexrecomp/emit.c`의 `mark_labels`와 `j` 출력 경로에서 `!is_function(an, in.target)` 조건을 제거해, 대상 주소가 현재 본문 범위(`[body_start, body_end)`)에 속하면 함수 진입점이더라도 `goto L_<addr>`로 출력하고 후방 분기(`in.target <= a`) 시 `PSP_LOOP`를 붙이도록 수정했습니다.
   * 재생성 결과(`%TEMP%\redmp1-build\gen-i032`, `8785` 함수 / `17215` 내부 진입점 / `144` 임포트)의 `dmp1_funcs_058.c`에서 `088616C8 j 0x0886167C`가 `PSP_LOOP(0x0886167Cu); goto L_0886167C;`로 생성됨을 확인했습니다.
2. **정적 점검 도구 확장 (`tools/lift_audit.py`)**
   * `self_tail_call` 불일치 규칙을 추가해 자기 본문 범위를 향한 tail-call을 검출하도록 했습니다(패치 전 `472`건 → 패치 후 `0`건).
   * Tarjan SCC(`find_tail_call_sccs`)로 본문 간 꼬리 호출 순환을 집계한 결과, 패치 전 `606`개에서 패치 후 `148`개(모두 크기 ≥ 2: 크기 14 1개, 크기 7 1개, 크기 5 3개 포함 총 5개, 크기 4 5개, 크기 3 13개, 크기 2 123개; 상위 5개: `0x0883E9E8` 군 14개, `0x0887651C` 군 7개, `0x0881414C` 군 5개, `0x0882B134` 군 5개, `0x08864608` 군 5개)가 남았습니다.
   * 또한 `ScorePlayerThread`의 `0x088615B0 → 0x08861658 → 0x0886167C → 0x088616D0 → j 0x088615B0`처럼 fall-through를 포함한 4-본문 외부 순환도 존재함을 확인했습니다(`docs/analysis/score-playback.md`, `docs/analysis/README.md`에 기록).
3. **`repsp` 게스트 스레드 호스트 스택 및 진단 연동 (`third_party/repsp` 브랜치 `i032-guest-stack`, `src/app/main.cpp`)**
   * `HostThreadOptions::stack_reserve_bytes`, `Scheduler::kDefaultGuestHostStackReserveBytes = 64 MiB`(reserve-only), `Scheduler::FormatHostStackStats()`를 추가했습니다(`third_party/repsp/docs/work-logs/20261115-i032-guest-stack.md`).
   * `src/app/main.cpp`의 `REDMP1_TRACE_GUEST` 요약 뒤에 `FormatHostStackStats()` 출력을 연결했습니다.

## 설계 질문 (교차 함수 꼬리 호출 순환)

패치 후에도 서로 다른 본문 간의 꼬리 호출 순환(`148`개 SCC)과 fall-through를 포함한 외부 순환(`0x088615B0..0x088616D0`)이 남아 있습니다. 이를 어떻게 다룰지 아래 선택지에 대한 설계 결정을 요청합니다.

1. **64 MiB 게스트 호스트 스택 예약 유지 + 실제 스택 증가 관찰 후 대응**: 현재 `ScorePlayerThread`가 6500 vblanks까지 증가하지 않았고 64 MiB 가상 예약으로 보호되므로, 실제 장시간 플레이에서 문제를 일으키는 SCC만 선별해 고칩니다.
2. **SCC 본문 병합 (`allegrexrecomp` 패치)**: 같은 SCC에 속한 본문들을 하나의 C 함수로 묶어 내부 `goto`로 변환합니다(가장 근본적이지만 lifter 분석 패치 범위가 큼).
3. **트램폴린 / 꼬리 호출 디스패치 루프**: SCC 내부 꼬리 호출을 직접 호출 대신 다음 대상 주소를 반환하는 while 루프로 바꿉니다(함수 경계를 유지하나 ABI 오버헤드 발생).

# Work Log: Eliminating Self-Loop Tail Calls and Reserving Guest Host Stacks (reDMP1 #32)

## Summary

Fixed the defect where `allegrexrecomp` lowered `j` instructions targeting an address owned by the same lifted body as self-recursive calls (`0004-j-owned-target-goto.patch`), added `self_tail_call` and cross-function tail-call SCC reporting to `tools/lift_audit.py`, and integrated `repsp` (`i032-guest-stack`) 64 MiB reserve-only guest host stacks with OS high-water reporting.

## Changes

1. **Local Lifter Patch (`patches/psprecomp/0004-j-owned-target-goto.patch`, `CMakeLists.txt`, `patches/psprecomp/README.md`)**
   * Removed `!is_function(an, in.target)` in `mark_labels` and `j` emission in `third_party/psprecomp/tools/allegrexrecomp/emit.c` so jumps targeting `[body_start, body_end)` emit `goto L_<addr>` (with `PSP_LOOP` for backward targets `in.target <= a`).
   * Verified in regenerated `dmp1_funcs_058.c` (`%TEMP%\redmp1-build\gen-i032`, `8785` functions, `17215` interior entries, `144` imports) that `088616C8 j 0x0886167C` emits `PSP_LOOP(0x0886167Cu); goto L_0886167C;`.
2. **Static Audit Tool (`tools/lift_audit.py`)**
   * Added `self_tail_call` mismatch detection (`472` pre-patch → `0` post-patch).
   * Added Tarjan SCC reporting (`find_tail_call_sccs`): `606` pre-patch → `148` post-patch (all `size >= 2`: 1x size 14, 1x size 7, 5x size 5, 5x size 4, 13x size 3, 123x size 2).
   * Documented the 4-body fall-through/tail-call outer cycle `0x088615B0 → 0x08861658 → 0x0886167C → 0x088616D0 → j 0x088615B0` in `docs/analysis/score-playback.md` and `docs/analysis/README.md`.
3. **`repsp` Guest Stack Integration (`third_party/repsp` branch `i032-guest-stack`, `src/app/main.cpp`)**
   * Added `HostThreadOptions::stack_reserve_bytes`, `Scheduler::kDefaultGuestHostStackReserveBytes = 64 MiB` (reserve-only), and `Scheduler::FormatHostStackStats()` (`third_party/repsp/docs/work-logs/20261115-i032-guest-stack.md`), printed under `REDMP1_TRACE_GUEST` in `src/app/main.cpp`.

## Design Question (Cross-Function Tail-Call Cycles)

Even after the patch, `148` cross-function tail-call SCCs and the fall-through-inclusive `0x088615B0..0x088616D0` cycle remain. Options for handling them:
1. Keep the 64 MiB reserve-only guest host stack and fix specific SCCs only if long gameplay reveals stack growth.
2. Merge bodies within each SCC into one C function in `allegrexrecomp` so cross-function tail calls become `goto`s.
3. Lower tail calls in SCCs via a trampoline dispatch loop.
