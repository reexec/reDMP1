# 작업 지시: 유틸리티 (issue #15)

설계: [20261114-i015](../design/20261114-i015-utility.md)
브랜치: `i015-utility`(main의 v0.0.7 커밋에서)
선행: [repsp issue #15](https://github.com/reexec/repsp/issues/15)(sceUtility). submodule `third_party/repsp`의 `i015-utility` 브랜치에서 함께 개발한다. reDMP1 커밋에는 `third_party/repsp` 포인터를 넣지 않는다.

1. 앱: utility 등록, `--save-dir`, `--dialog-answer`, 정지 보고의 유틸리티 통계(설계 §3).
2. 실행과 진행(설계 §2). 정지는 repsp submodule 브랜치에서 구현·수정하고 probe를 더한 뒤 다시 실행한다. 계속 도는 화면에 이르면 `--max-vblanks`로 끝낸다. 고칠 것이 여섯 건을 넘거나 설계 판단이 필요하면 멈추고 질문으로 올린다.
3. CTest: `app_boot` 유지, 세이브 디렉터리는 빌드 디렉터리 안의 임시 경로(설계 §3, §5).
4. 문서: `docs/analysis/savedata.md`(새 파일, 설계 §4)와 색인, `docs/analysis/first-frame.md`(이어 쓰기), `docs/guides/running-and-tracing.md`(새 옵션), `ARCHITECTURE.md`, 작업 로그 `docs/work-logs/20261114-i015-utility.md`(repsp 쪽 추가 변경, 프레임 덤프를 남긴 위치, 질문 포함).
5. 검증: 설계 §5.

지킬 것: 게임 데이터, 생성 코드, 프레임 덤프, 입력 스크립트, 세이브 데이터, 실행 로그 원본은 커밋하지 않는다. 분석 문서에는 원본 게임 사실만. 문서와 로그에 사용자 계정 이름이 든 절대 경로를 쓰지 않는다(`%TEMP%` 같은 표기를 쓴다). 작업 단위마다 커밋, 제목 끝에 `(#15)`. push·PR·merge·tag 금지. psprecomp 원격에는 아무것도 하지 않는다.

작업 환경에서 git 커밋이나 WSL 실행이 막히면 우회하지 말고, 변경을 작업 트리에 둔 채 작업 로그와 보고에 그 사실을 적는다.

완료 기준: 설계 §5의 1~6(3은 리뷰어가 확인).
