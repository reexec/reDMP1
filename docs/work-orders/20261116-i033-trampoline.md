# 작업 지시: 트램펄린 (issue #33)

설계: [20261116-i033](../design/20261116-i033-trampoline.md)
브랜치: `i033-trampoline`(main의 v0.0.18 커밋에서)

1. lifter 로컬 패치 `patches/psprecomp/0005-*.patch`: `emit`의 트램펄린 선택 사항(기본 꺼짐; 끄면 출력이 지금과 바이트 단위로 같음). CMake 패치 목록에 등록(설계 §2, §3).
2. `src/recomp_abi/`: `psp_next`, `psp_run`, `psp_call_from_host`·`psp_dispatch`의 트램펄린 경로, 게스트 되감기(`psp_cpu.unwind`)와 정지 뒤의 처리(설계 §2).
3. `scripts/recomp/regenerate.py`·`lift.json`에 트램펄린을 켜는 설정, 다시 생성(`python scripts/recomp/regenerate.py roms`; 출력된 lifter 경로가 방금 빌드한 것인지 확인).
4. `tools/lift_audit.py`의 새 규칙(설계 §4의 1).
5. 측정: 최적화하지 않은 생성 코드 구성의 스택(트램펄린 켬/끔), Release의 CPU 시간과 표시 간격(설계 §4의 2~3).
6. 문서: `patches/psprecomp/README.md`, 작업 로그 `docs/work-logs/20261116-i033-trampoline.md`(측정표, 질문).
7. 검증: 설계 §4의 1~6.

참고: 패치 0001·0004는 upstream PR(sp00nznet/psprecomp#36, #35)과 같은 내용이다. 0005는 그 위에 쌓되 0001·0003·0004를 바꾸지 않는다. 기존 패치 파일이 줄 끝·공백 차이로 적용되도록 CMake가 `git apply --ignore-whitespace`를 쓴다는 점을 고려한다.

지킬 것: 생성 코드를 손으로 고치지 않는다. psprecomp 원격에는 아무것도 하지 않는다(push, PR, issue 금지). repsp 계약을 바꾸지 않는다(필요하면 질문). 게스트 스레드의 64 MiB 예약과 Debug의 생성 코드 최적화 설정은 이번에 바꾸지 않는다. 게임 데이터, 생성 코드, 실행 로그 원본, 덤프, 입력 스크립트, 세이브 데이터는 커밋하지 않는다. 문서와 로그에 사용자 계정 이름이 든 절대 경로를 쓰지 않는다. PPSSPP(GPL) 코드는 보지 않는다. 작업 단위마다 커밋, 제목 끝에 `(#33)`. push·PR·merge·tag 금지.

작업 환경에서 git 커밋, WSL 실행, 저장소 안 생성 코드 쓰기가 막히면 우회하지 말고, 변경을 작업 트리에 둔 채 작업 로그와 보고에 그 사실을 적는다(생성 코드는 `--outdir`와 `REDMP1_GENERATED_DIR`로 임시 디렉터리에). Linux에서도 빌드되도록 GCC 경고(`-Wall -Wextra -Wpedantic -Werror`)를 미리 살피고, Visual Studio 생성기(`scripts\build_win64.bat`)로도 Debug/Release를 빌드한다.

완료 기준: 설계 §4의 1~6(7은 사용자가 확인).

# Work order: trampoline (issue #33)

Design: [20261116-i033](../design/20261116-i033-trampoline.md)
Branch: `i033-trampoline` (from the v0.0.18 commit on main)

(1) The local lifter patch `patches/psprecomp/0005-*.patch`: a trampoline option for `emit` (off by default; off, output byte-identical to today's), registered in the CMake patch list (design §2, §3). (2) `src/recomp_abi/`: `psp_next`, `psp_run`, the trampoline paths of `psp_call_from_host` and `psp_dispatch`, guest unwinding (`psp_cpu.unwind`) and handling after stops (design §2). (3) A setting in `scripts/recomp/regenerate.py` and `lift.json` that turns the option on, and regeneration (`python scripts/recomp/regenerate.py roms`; check that the printed lifter path is the one just built). (4) The new rule in `tools/lift_audit.py` (design §4, item 1). (5) Measurement: stack in the configuration with unoptimized generated code (trampoline on and off), CPU time and presentation intervals in Release (design §4, items 2-3). (6) Documents: `patches/psprecomp/README.md` and the work log `docs/work-logs/20261116-i033-trampoline.md` (measurement tables, questions). (7) Verify: design §4, items 1-6.

Note: patches 0001 and 0004 match the upstream PRs (sp00nznet/psprecomp#36, #35). 0005 stacks on top and does not change 0001, 0003 or 0004. CMake applies patches with `git apply --ignore-whitespace`, which tolerates line-ending and whitespace differences.

Must hold: generated code is never edited by hand; nothing is done on psprecomp's remote (no push, pull request or issue); repsp's contracts do not change (raise a question if needed); the guest threads' 64 MiB reservation and optimizing generated code in Debug are not changed this time; game data, generated code, raw run logs, dumps, input scripts and save data are never committed; no absolute path containing a user account name in documents or logs; PPSSPP (GPL) code is not read; commit per unit of work with titles ending in `(#33)`; no push, pull request, merge or tag.

If git commits, WSL, or writes to the in-repository generated code are blocked in the working environment, do not work around it: leave the changes in the working tree and say so in the work log and the report (generated code goes to a temporary directory through `--outdir` and `REDMP1_GENERATED_DIR`). Watch for GCC warnings (`-Wall -Wextra -Wpedantic -Werror`) so the Linux build passes, and also build Debug/Release with the Visual Studio generator (`scripts\build_win64.bat`).

Done when: design §4, items 1-6 (item 7 is the user's check).
