# 작업 지시: 플레이 진입 (issue #20)

설계: [20261114-i020](../design/20261114-i020-play-entry.md)
브랜치: `i020-play-entry`(main의 v0.0.9 커밋에서)
함께: [repsp issue #19](https://github.com/reexec/repsp/issues/19). submodule `third_party/repsp`의 `i019-play-entry` 브랜치에서 함께 개발한다. reDMP1 커밋에는 `third_party/repsp` 포인터를 넣지 않는다.

1. 화면마다 나아가며 입력 스크립트를 늘린다(설계 §2).
2. 정지와 결함은 원인을 확정한 뒤 원인이 있는 곳에서 고친다(설계 §3). 게스트 쪽 이상은 lift 결과를 먼저 의심한다. 설계 판단이 필요하면 고치지 말고 질문으로 올린다.
3. 플레이 화면에 이르면 `--max-vblanks`로 끝낸다.
4. 문서: `docs/analysis/scene-flow.md`·`audio.md`·`first-frame.md`(이어 쓰기, 설계 §4), lifter 패치를 더했다면 `patches/psprecomp/README.md`, 옵션이 바뀌었다면 `docs/guides/running-and-tracing.md`, 작업 로그 `docs/work-logs/20261114-i020-play-entry.md`(스크립트 내용, 결함별 증거, repsp 쪽 변경, 프레임 덤프를 남긴 위치, 질문 포함).
5. 검증: 설계 §5.

지킬 것: 게임 데이터, 생성 코드, 프레임 덤프, 입력 스크립트, 세이브 데이터, 실행 로그 원본은 커밋하지 않는다. 생성 코드를 손으로 고치지 않는다. 분석 문서에는 원본 게임 사실만. 문서와 로그에 사용자 계정 이름이 든 절대 경로를 쓰지 않는다. PPSSPP(GPL)와 FFmpeg(LGPL) 코드는 보지 않는다. 작업 단위마다 커밋, 제목 끝에 `(#20)`. push·PR·merge·tag 금지. psprecomp 원격에는 아무것도 하지 않는다.

작업 환경에서 git 커밋, WSL 실행, 저장소 안 생성 코드 디렉터리 쓰기가 막히면 우회하지 말고, 변경을 작업 트리에 두고(생성 코드는 `REDMP1_GENERATED_DIR`로 임시 디렉터리에) 작업 로그와 보고에 그 사실을 적는다. Linux에서도 빌드되도록 GCC 경고(`-Wall -Wextra -Wpedantic -Werror`)를 미리 살핀다.
