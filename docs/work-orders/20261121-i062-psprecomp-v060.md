# 작업 지시: psprecomp upstream v0.6.0으로 이동 (issue #62)

설계: [20261121-i062-psprecomp-v060](../design/20261121-i062-psprecomp-v060.md)

브랜치 `i062-psprecomp-v060`(main의 v0.0.30 커밋에서)을 만들어 두었다. 첫 커밋에 설계 §3의 1~2가 들어 있다.
* submodule `third_party/psprecomp`가 `14749c1`(v0.6.0)이다.
* 패치 0001, 0003, 0004, 0006을 지웠다.
* 0005는 다시 만들었다.
* `CMakeLists.txt`의 패치 목록을 맞췄다.

다음 단위로 나눠 진행하고, 단위마다 커밋한다.

1. **패치 README**(설계 §3의 2): `patches/psprecomp/README.md`의 기준 커밋, upstream 상태 표, 패치 설명을 맞춘다. 남는 패치는 0005 하나다. upstream에 들어간 패치는 표에 "v0.6.0에 들어감"으로 한 줄씩 남긴다.
2. **ABI 어댑터와 probe**(설계 §3의 3, 5): `psp_call_guest_fn`, `psp_call_guest_addr`를 추가하고, `src/recomp_abi/README.md`와 `recomp_abi_probe`를 고친다.
3. **다시 생성과 빌드**(설계 §3의 4, §4의 1~2):
   * 새로 빌드한 lifter(`ALLEGREXRECOMP` 환경 변수로 경로를 지정)로 `scripts/recomp/regenerate.py`를 돌린다.
   * 차이를 §2의 표와 비교해 작업 로그에 적는다.
   * Windows의 세 구성을 빌드하고 CTest를 돌린다.
4. **게임 확인**(설계 §4의 3~5):
   * 입력 스크립트 `%TEMP%\redmp1-build\i041-keysound-script.txt`와 `--autoplay`로 한 곡을 돈다. Release와 Debug에서 각각 돈다.
   * 같은 장면의 FPS를 v0.0.30 빌드와 비교한다.
5. **문서**: 작업 로그 `docs/work-logs/20261121-i062-psprecomp-v060.md`.

지킬 것:
* 생성 코드를 손으로 고치지 않는다. submodule 안의 파일도 고치지 않는다.
* repsp에는 게임 정보와 psprecomp 의존을 넣지 않는다.
* PPSSPP 등 GPL 코드는 보지 않는다.
* 게임 데이터, 생성 코드, 로그 원본, 덤프, 캡처, 입력 스크립트, 세이브 데이터, `redmp1.ini` 실물은 커밋하지 않는다.
* 사용자 경로는 쓰지 않는다.
* probe는 창 없이 돌고, 실패해도 대화상자 없이 끝나며, 스레드 타이밍에 기대지 않는다.
* 커밋 제목 끝에 `(#62)`를 붙인다.
* push·PR·merge·tag는 하지 않는다.

git 커밋이나 WSL이 막히면 우회하지 말고, 변경을 작업 트리에 둔 채 단위별로 무엇을 바꿨는지 보고에 적는다. GCC 경고(`-Wall -Wextra -Wpedantic -Werror`)를 살핀다.

완료 기준: 설계 §4의 1~5(6은 사용자가 확인). 확인이 필요한 결정은 질문으로 올린다.

# Work order: move psprecomp to upstream v0.6.0 (issue #62)

Branch `i062-psprecomp-v060` (from the v0.0.30 commit on main) is created. Its first commit holds design §3 items 1-2:
* The submodule `third_party/psprecomp` is at `14749c1` (v0.6.0).
* Patches 0001, 0003, 0004 and 0006 are deleted.
* 0005 is regenerated.
* The patch list in `CMakeLists.txt` is updated.

Work in these units, committing each:

1. **Patch README** (design §3 item 2): update the base commit, upstream status table and patch descriptions in `patches/psprecomp/README.md`. Only 0005 remains. Keep one row per merged patch in the table, marked "in v0.6.0".
2. **ABI adapter and probe** (design §3 items 3 and 5): add `psp_call_guest_fn` and `psp_call_guest_addr`, and update `src/recomp_abi/README.md` and `recomp_abi_probe`.

   * Compare the difference with §2's table and record it in the work log.
   * Build the three Windows configurations and run CTest.
4. **Game check** (design §4 items 3-5):
   * Play one song with the input script at `%TEMP%\redmp1-build\i041-keysound-script.txt` and `--autoplay`, once in Release and once in Debug.
   * Compare FPS on the same scene with a v0.0.30 build.
5. **Documents**: the work log `docs/work-logs/20261121-i062-psprecomp-v060.md`.

**Must hold**:
* Generated code is never edited by hand, and neither are files inside the submodule.
* No game information or psprecomp dependency in repsp.
* PPSSPP and other GPL code is not read.
* Never commit game data, generated code, raw logs, dumps, captures, input scripts, save data, or an actual `redmp1.ini`.
* No user paths.
* Probes run without a window, exit without a dialog on failure, and do not depend on thread timing.
* Commit titles end in `(#62)`.
* No push, pull request, merge or tag.

If git commits or WSL are blocked, do not work around it. Leave the changes in the working tree and report what changed in each unit. Watch for GCC warnings (`-Wall -Wextra -Wpedantic -Werror`).

**Done when**: design §4 items 1-5 pass (item 6 is the user's check). Raise any decision that needs confirming as a question.
