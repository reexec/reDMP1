# 작업 지시: 내부 UI, 설정, 창 제목·FPS, 창 단축키 (issue #47, repsp #48)

설계: [20261118-i047](../design/20261118-i047-overlay.md)
브랜치: reDMP1 `i047-overlay`(main의 v0.0.23 커밋에서), repsp는 submodule `third_party/repsp`의 `i48-overlay`(main `8048c80` 위에 Dear ImGui submodule 커밋 `f4d9908`)
참고 구현 사본: `%TEMP%\redmp1-build\borrow\` (rexbox, reCT3. 저장소에 복사해 넣지 말고, 필요한 코드를 repsp/reDMP1 구조와 이름으로 옮긴다)

다음 단위로 나눠 진행하고, 단위마다 커밋한다.

1. **repsp 1단계**: `imgui` 라이브러리(CMake), 오버레이 계약과 ImGui 수명(OpenGL 렌더러일 때만), Tab과 LB+RB+Y 토글, 메뉴가 열려 있는 동안의 입력 차단(설계 §3.1~3.2)
2. **repsp 2단계**: 창 제목·FPS(창 스레드에서만), Alt+1~6, Alt+Enter, 더블클릭, Ctrl+1~8, Alt·Ctrl 조합이 게임 입력으로 새지 않게 하기(설계 §3.3~3.4)
3. **repsp 3단계**: 표시와 GL 옵션(창 배율, 전체화면, VSync, 화면 비율, 출력 필터, 렌더링 배율, MSAA, 텍스처 필터링)과 통계 원천(설계 §3.5)
4. **reDMP1**: `redmp1.ini`, 명령줄과의 우선순위, 설정 메뉴(Info, Graphics, Input)와 통계 창(설계 §4)
5. **probe와 측정**(설계 §5의 1~6), **문서**(설계 §6)

지킬 것:
* 생성 코드를 손으로 고치지 않는다.
* repsp에는 게임 정보와 psprecomp 의존을 넣지 않는다.
* PPSSPP 등 GPL 코드는 보지 않는다(rexbox·reCT3는 같은 조직의 코드라 참고해도 된다).
* 게임 데이터, 생성 코드, 로그 원본, 덤프, 캡처, 입력 스크립트, 세이브 데이터, `redmp1.ini` 실물은 커밋하지 않는다.
* 사용자 경로는 쓰지 않는다.
* probe는 창 없이 돌고, 실패해도 창을 띄우지 않으며, 스레드 타이밍에 기대지 않는다.
* 커밋 제목 끝에 reDMP1은 `(#47)`, repsp는 `(#48)`을 붙인다.
* push·PR·merge·tag는 하지 않는다.

작업 환경에서 git 커밋이나 WSL이 막히면 우회하지 말고, 변경을 작업 트리에 둔 채 단위별로 무엇을 바꿨는지 보고에 적는다. GCC 경고(`-Wall -Wextra -Wpedantic -Werror`)를 살핀다. Dear ImGui 소스는 경고 대상에서 뺀다.

완료 기준: 설계 §5의 1~6(7은 사용자가 확인). 확인이 필요한 결정(예: GPU 메모리를 구할 수 없을 때 표시, MSAA와 render-to-texture 충돌)은 질문으로 올린다.

# Work order: in-game UI, settings, window title and FPS, window shortcuts (issue #47, repsp #48)

Design: [20261118-i047](../design/20261118-i047-overlay.md)

Branches:
* reDMP1: `i047-overlay`, from the v0.0.23 commit on main.
* repsp: `i48-overlay` in the submodule `third_party/repsp`. It is main `8048c80` plus the Dear ImGui submodule commit `f4d9908`.

Reference copies are in `%TEMP%\redmp1-build\borrow\` (rexbox and reCT3). Do not copy them into the repositories; move the code you need into repsp/reDMP1 structure and names.

Work in these units, committing each:

1. **repsp, step 1** (design §3.1-3.2):
   * the `imgui` library (CMake);
   * the overlay contract and ImGui lifetime (OpenGL renderer only);
   * the Tab and LB+RB+Y toggle;
   * withholding input while the menu is open.
2. **repsp, step 2** (design §3.3-3.4):
   * the title and FPS (on the window's thread only);
   * Alt+1..6, Alt+Enter, double click and Ctrl+1..8;
   * keeping Alt and Ctrl combinations out of game input.
3. **repsp, step 3** (design §3.5):
   * display and GL options: window scale, fullscreen, VSync, aspect ratio, output filter, rendering scale, MSAA and texture filtering;
   * stats sources.
4. **reDMP1** (design §4): `redmp1.ini`, precedence against the command line, the settings menu (Info, Graphics, Input) and the stats window.
5. **Probes and measurement** (design §5, items 1-6), and **documents** (design §6).

**Must hold**:
* Generated code is never edited by hand.
* No game information or psprecomp dependency in repsp.
* PPSSPP and other GPL code is not read. rexbox and reCT3 are the organisation's own code and may be consulted.
* Never commit game data, generated code, raw logs, dumps, captures, input scripts, save data, or an actual `redmp1.ini`.
* No user paths.
* Probes run without a window, exit without a dialog on failure, and do not depend on thread timing.
* Commit titles end in `(#47)` for reDMP1 and `(#48)` for repsp.
* No push, pull request, merge or tag.

If git commits or WSL are blocked, do not work around it. Leave the changes in the working tree and report what changed in each unit. Watch for GCC warnings (`-Wall -Wextra -Wpedantic -Werror`), excluding the Dear ImGui sources.

**Done when**: design §5, items 1-6 pass (item 7 is the user's check). Raise any decision that needs confirming as a question, for example what to show when GPU memory cannot be obtained, or a conflict between MSAA and render-to-texture.
