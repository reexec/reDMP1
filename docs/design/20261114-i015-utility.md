# 설계: 유틸리티 — sceUtility를 앱에 연결하고 로딩 화면 너머로 진행 (issue #15)

## 1. 요구사항

* repsp의 sceUtility HLE([repsp issue #15](https://github.com/reexec/repsp/issues/15))를 앱에 연결한다. 부팅이 멈추던 `sceUtilitySavedataInitStart` 너머로 진행한다.
* 이로써 게임이 import하는 라이브러리를 모두 다룬다. issue #9·#11·#13과 같은 방식으로 계속 나아간다(§2).
* 다이얼로그는 지금은 그리지 않는다. 메시지 다이얼로그의 답은 앱 옵션으로 정한다(§3).
* 게임이 세이브 데이터와 다이얼로그를 쓰는 방식, 그 뒤에 그리는 것을 원본 게임의 사실로 `docs/analysis/`에 기록한다.

## 2. 진행 범위

* **다루는 라이브러리**: 게임이 import하는 20개 전부.
* 정지가 미구현 함수나 결함(미구현 세이브 데이터 모드, 미구현 GE 명령·SIGNAL 동작, 그리지 않는 primitive, 지원하지 않는 텍스처 형식 포함)이면, repsp submodule 브랜치에서 구현하거나 고치고 다시 실행한다. 추가한 것은 probe로 검사하고, 작업 로그에 적는다.
* 설계 판단이 필요한 결함(스케줄러 의미 변경, 계약 변경, 디코더 문제, 다이얼로그를 그려야만 진행되는 상황)은 고치지 말고 작업 로그의 질문으로 올린다.
* **끝내는 지점**: 입력을 기다리며 계속 도는 화면(타이틀 화면 등)에 이르면 `--max-vblanks`로 끝내고 그 화면을 프레임 덤프로 남긴다. 그 화면에서 `--input-script`로 한 단계 더 들어가 보는 것은 선택이다. 고칠 것이 여섯 건을 넘으면 거기서 멈추고 남은 것을 질문으로 올린다.
* 실행 스크립트(동영상 건너뛰기 등)는 저장소에 넣지 않는다.

## 3. 앱 옵션

* `--save-dir <path>`: 세이브 데이터를 둘 호스트 디렉터리. 기본값은 플랫폼의 사용자 데이터 디렉터리 아래(`SDL_GetPrefPath` 계열, repsp platform에 해당 기능이 없으면 platform에 더한다) `savedata/`다. 저장소 안이나 게임 데이터 디렉터리 안을 기본값으로 쓰지 않는다.
* `--dialog-answer <yes|no>`: 그리지 않는 예/아니오 다이얼로그의 답(기본 `yes`). repsp `hle::utility::SetDialogPolicy`에 연결한다.
* CTest는 빌드 디렉터리 안의 임시 세이브 디렉터리를 `--save-dir`로 주고, 실행 전에 비운다(실행마다 같은 결과).
* 정지 보고에 유틸리티 통계("dialog UI: not drawn" 포함)를 더한다.

## 4. 기록

* `docs/analysis/savedata.md`(새 파일): 세이브 데이터를 부르는 코드 경로와 시점, 쓰는 모드, `gameName`·`saveName`·`fileName`, 데이터 크기, `PARAM.SFO`에 넣는 제목·설명 글, 세이브가 없을 때와 있을 때의 분기, 메시지 다이얼로그의 글과 선택지, 상태를 확인하는 호출 순서.
* `docs/analysis/first-frame.md`에 이어서: 정지 또는 한도까지의 HLE 순서, 리스트·primitive 통계, 쓴 텍스처 형식, 화면 내용의 글 서술(이미지는 저장소에 넣지 않는다).
* 원본 게임의 사실만 적는다. 사용자 덤프의 위치나 이름, 사용자 계정 이름이 든 경로는 적지 않는다.

## 5. 이번 task의 검증

1. 로컬: 오프닝을 건너뛰는 실행이 `sceUtilitySavedataInitStart`를 지나, 계속 도는 화면의 vblank 한도 (e)로 끝나거나 §2의 질문 지점에서 멈춘다. 디스패치 미스, 교착이 없다.
2. 로컬: 세이브가 없는 상태와 (세이브를 쓰는 지점에 이르렀다면) 있는 상태를 각각 실행해 분기를 기록한다.
3. 로컬: 화면이 바뀌는 지점의 프레임 덤프를 남기고 위치를 작업 로그에 적는다(리뷰어가 확인; 커밋하지 않는다).
4. 로컬: 3회 실행을 비교하고 차이의 원인을 기록한다.
5. CTest `app_boot`는 지금의 종료 지점(동영상 재생 중의 한도)을 유지한다. 입력 스크립트가 필요한 새 지점은 CTest에 넣지 않는다.
6. Win64 Debug/Release와 Linux x64 빌드·CTest, CI 통과. 게임 데이터가 없는 구성(`REDMP1_HAVE_RECOMP=0`)도 경고 없이 빌드된다.

# Design: utility — wiring sceUtility into the app and running on past the loading screen (issue #15)

## 1. Requirements

Wire repsp's sceUtility HLE ([repsp issue #15](https://github.com/reexec/repsp/issues/15)) into the app and run past `sceUtilitySavedataInitStart`, where the boot stopped. With this every library the game imports is covered, and the run keeps going as in issues #9, #11 and #13 (§2). Dialogs are not drawn for now; the answer to a message dialog comes from an app option (§3). How the game uses save data and dialogs, and what it draws afterwards, is recorded in `docs/analysis/` as facts about the original game.

## 2. How far to go

All 20 imported libraries are covered. A stop at an unimplemented function or a defect (including an unimplemented save data mode, an undecoded GE command, a SIGNAL behaviour, an undrawn primitive or an unsupported texture format) is implemented or fixed on the repsp submodule branch, with probes, recorded in the work log, and the run repeated. A defect that needs a design decision (scheduler semantics, a contract change, a decoder problem, a situation that only proceeds if a dialog is drawn) is not fixed but raised as a question in the work log. **End point**: on reaching a screen that keeps running while waiting for input (a title screen, for instance) the run is ended with `--max-vblanks` and that screen kept as a frame dump; going one step further with `--input-script` is optional. After more than six fixes the task stops and the rest is raised as questions. Run scripts are not committed.

## 3. App options

`--save-dir <path>` names the host directory for save data; the default is `savedata/` under the platform's per-user data directory (the `SDL_GetPrefPath` family; added to repsp's platform layer if it is missing), never inside the repository or the game data directory. `--dialog-answer <yes|no>` answers undrawn yes/no dialogs (default `yes`) through repsp's `hle::utility::SetDialogPolicy`. CTest passes a temporary save directory inside the build directory as `--save-dir` and empties it before each run, so every run gives the same result. The stop report gains the utility statistics (including "dialog UI: not drawn").

## 4. Record

`docs/analysis/savedata.md` (new): the code path and moment of the save data calls, the modes used, `gameName`, `saveName` and `fileName`, the data size, the title and description text put into `PARAM.SFO`, the branches with and without existing save data, the text and choices of message dialogs, and the order of the status calls. Continuing `docs/analysis/first-frame.md`: the HLE order up to the stop or limit, list and primitive statistics, texture formats used and a written description of the picture (no image in the repository). Facts about the original game only — no location or name of the user's dump, and no path containing a user account name.

## 5. Verification for this task

1. Local: the run that skips the opening goes past `sceUtilitySavedataInitStart` and ends at the vblank limit (e) on a screen that keeps running, or stops at a question point from §2; no dispatch miss or deadlock.
2. Local: runs without save data and (if the run reaches a point that saves) with it, recording the branches.
3. Local: frame dumps where the picture changes are kept and their location goes to the work log (checked by the reviewer; never committed).
4. Local: three runs are compared and the cause of any difference recorded.
5. CTest `app_boot` keeps its present end point (the limit during movie playback); a new point that needs an input script is not added to CTest.
6. Win64 Debug/Release and Linux x64 builds and CTest, and CI, pass; the configuration without game data (`REDMP1_HAVE_RECOMP=0`) builds without warnings.
