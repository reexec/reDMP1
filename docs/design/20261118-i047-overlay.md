# 설계: 내부 UI(Dear ImGui), 설정, 창 제목·FPS, 창 단축키 (issue #47, repsp #48)

## 1. 요구사항

* 사용자 요청(2026-11-18): reCT3와 rexbox에 있는 다음 기능을 가져온다.
  1. Dear ImGui로 만든 내부 UI와 내부 설정 가운데 가능한 것을 모두 가져온다(FPS 그래프, 그래픽 옵션 포함).
  2. 창 제목 형식과 FPS 표시, 단축키로 창 크기 조절, 전체화면 전환(마우스 클릭 포함)을 가져온다.
* **사용자 결정(2026-11-18)**:
  * Graphics 옵션: 렌더링 해상도, 창 크기, 전체화면, VSync를 기본으로 넣고, 화면 비율·MSAA·텍스처 필터링·화면 출력 필터를 추가한다.
  * 내부 UI는 OpenGL 렌더러에서만 동작한다. 소프트웨어 렌더러에서는 창 제목과 단축키만 동작한다.
  * 창 크기 단축키는 Alt+1~6(480x272의 1~6배)이다.
  * 게임패드로 메뉴를 여닫는 조합을 넣는다.
* **참고 구현**(리뷰어가 `%TEMP%\redmp1-build\borrow\`에 사본을 둔다. 저장소에는 넣지 않는다):
  * rexbox `include/rexbox/platform/overlay.h`, `src/platform/sdl/overlay_sdl.cpp`, `src/platform/sdl/display_sdl.cpp`
  * reCT3 `src/app/settings.{h,cpp}`, `settings_ui.{h,cpp}`, `main.cpp`
  * 같은 조직의 저장소이므로 구조와 코드를 가져와도 된다. 다만 이름과 네임스페이스는 repsp/reDMP1 것으로 바꾼다.

## 2. 나눔

* **repsp(플랫폼, 게임 무관)**:
  * 오버레이 계약과 ImGui 수명
  * 창 제목·FPS
  * 단축키
  * 게임패드 조합과 메뉴가 열려 있는 동안의 입력 차단
  * 표시 옵션(비율, 출력 필터, VSync, 전체화면, 창 배율)
  * GL 백엔드 옵션(렌더링 배율, MSAA, 텍스처 필터링)
  * 통계 원천(표시 FPS, 프로세스 메모리, GPU 메모리)
* **reDMP1(앱)**: 설정 파일(`redmp1.ini`), 설정 메뉴의 내용(탭과 위젯), 통계 창, 명령줄 옵션과 설정 파일의 우선순위.
* repsp에는 게임 이름과 게임 정보를 넣지 않는다. 창 제목의 앞부분은 앱이 정한다.

## 3. repsp

### 3.1 Dear ImGui
* `third_party/imgui`(v1.93.0, MIT, rexbox와 같은 커밋)를 submodule로 붙였다. 리뷰어가 커밋했다.
* `imgui` 정적 라이브러리를 만든다(core와 `backends/imgui_impl_sdl3.cpp`, `imgui_impl_opengl3.cpp`). `THIRD_PARTY_NOTICES.md`에 라이선스를 적는다.
* 앱은 `imgui.h`를 직접 include해 위젯을 그린다. 그러려면 include 경로를 공개해야 한다.

### 3.2 오버레이 계약(`include/repsp/platform/overlay.h`)
* rexbox와 같은 형태로 만든다.
  * `SetOverlayBuilder(std::function<void()>)`: 매 표시마다 `NewFrame`과 `Render` 사이에서 부른다.
  * `RenderOverlay()`: 플랫폼이 표시 직전에 UI 스레드(GL 문맥 소유)에서 부른다. GL 상태는 되돌린다.
  * `OverlayVisible()` / `SetOverlayVisible()`
* 메뉴 토글은 키보드 Tab과 게임패드 LB+RB+Y(PSP 매핑으로 L+R+세모)다.
* 메뉴가 열려 있는 동안에는 게임 입력을 막는다. 게임은 아무것도 누르지 않은 상태를 본다. 입력은 오버레이로 간다.
* ImGui는 OpenGL 렌더러일 때만 만든다. 소프트웨어 렌더러에서는 빌더를 부르지 않는다.
* ImGui의 `.ini` 저장은 끈다(`io.IniFilename = nullptr`). 창 위치는 앱 설정이 맡는다.
* 화면 크기에 맞춘 UI 배율(OSD scale)은 rexbox 방식을 따른다.

### 3.3 창 제목과 FPS
* 형식(rexbox와 같음): `<앱 제목> - OpenGL <major>.<minor> - FPS : <n.n>`. 소프트웨어 렌더러에서는 `<앱 제목> - Software - FPS : <n.n>`이다.
* FPS는 약 1초 동안의 실제 표시 횟수(`sceDisplaySetFrameBuf`로 나간 화면 수)에서 구한다.
* 제목은 창 스레드에서만 바꾼다(rexbox issue #62와 같은 이유).
* `SetDisplayTitle()`로 앱이 앞부분을 정한다.

### 3.4 단축키와 마우스

| 입력 | 동작 |
|---|---|
| Alt+1~6 | 창 크기를 480x272의 1~6배로 바꾼다. 전체화면이나 최대화 상태면 먼저 해제한다. |
| Alt+Enter, 왼쪽 버튼 더블클릭 | 전체화면을 토글한다(데스크톱 해상도의 테두리 없는 창, 디스플레이 모드는 바꾸지 않음). |
| Ctrl+1~8 | 렌더링 해상도(내부 배율 1~8)를 바꾼다. |
| Tab, LB+RB+Y | 메뉴를 토글한다. |

* Alt나 Ctrl이 눌린 키 입력은 게임에 전달하지 않는다. 예를 들어 Enter는 START에 매핑돼 있으므로, Alt+Enter가 START로 새면 안 된다.
* 메뉴가 열려 있을 때는 마우스 더블클릭을 ImGui가 받는다. 메뉴 창 밖에서 한 더블클릭만 전체화면을 토글한다.

### 3.5 표시와 GL 옵션(런타임에 바꿀 수 있어야 함)
* **창 배율**(1~6), **전체화면**, **VSync**(켬/끔. 가능하면 adaptive)
* **화면 비율**: 원본 비율 유지(레터박스) / 창에 맞춰 늘리기 / 정수 배율만(남는 곳은 검게)
* **화면 출력 필터**: 최근접 / 선형. 최종 화면을 창 크기로 늘릴 때 쓴다.
* **렌더링 해상도**: 내부 배율 1~8. 기존 `--scale`, `SetInternalScale`과 같은 값이다.
* **MSAA**: 끔 / 2x / 4x / 8x. GL 렌더 타깃에 적용하고, 지원하지 않는 값은 지원하는 가장 큰 값으로 내린다. 렌더 타깃을 텍스처로 읽는 경우(render-to-texture)에는 resolve가 맞아야 한다.
* **텍스처 필터링**: 원본(게임이 정한 대로) / 항상 선형 / 이방성 2x~16x(지원 범위 안에서)
* **통계 원천**: 표시 FPS, 프로세스 메모리(작업 집합), GPU 메모리(드라이버가 알려 주면. 없으면 이 HLE가 만든 텍스처·타깃의 합)

## 4. reDMP1

### 4.1 설정 파일
* reCT3와 같은 규칙을 따른다. 실행 파일 옆의 `redmp1.ini`를 쓰고, 그 폴더에 쓸 수 없으면 사용자 설정 폴더를 쓴다.
* 알 수 없는 키나 잘못된 값은 기본값으로 둔다. 저장은 임시 파일을 거친다.
* 항목: 창 배율, 전체화면, VSync, 화면 비율, 출력 필터, 렌더링 해상도, MSAA, 텍스처 필터링, 통계 창 표시 항목(FPS·메모리·GPU 메모리), 통계 창 위치
* **우선순위**: 명령줄 옵션(`--scale`, `--renderer` 등)이 설정 파일보다 앞선다. 명령줄로 정한 값은 그 실행에서만 쓰고 파일에 쓰지 않는다. 메뉴에서 바꾸면 파일에 저장한다.

### 4.2 설정 메뉴(`src/app/` 또는 기존 앱 디렉터리)
* **Info**: 버전, 빌드 시각, 플랫폼·구성, 커밋, 게임(디스크 이미지 이름이 아니라 게임 ID와 제목), 렌더러와 GL 정보, 메모리
* **Graphics**: 3.5의 옵션과 통계 창 항목 선택. 즉시 적용되지 않는 값은 reCT3의 Tracked 방식으로 "적용 중"을 보인다.
* **Input**: 키보드와 게임패드 매핑표(읽기 전용), 메뉴 단축키 안내
* **통계 창**: FPS 그래프(0.5초 구간, reCT3 방식)와 메모리 그래프. 위치는 끌어서 옮기고 저장한다.
* UI 문자열은 영어다(reCT3와 같음).

## 5. 측정과 검증

1. 창 모드에서 확인한다.
   * Tab과 LB+RB+Y로 메뉴가 열고 닫힌다.
   * 메뉴가 열려 있는 동안 게임이 입력을 받지 않는다.
   * 각 옵션이 바로(또는 표시된 대로) 적용되고, 다시 실행하면 유지된다.
   * Alt+1~6, Alt+Enter, 더블클릭, Ctrl+1~8이 동작하고, Alt+Enter가 START로 새지 않는다.
   * 제목줄 FPS가 실제 표시 횟수와 맞다.
2. 성능: 메뉴를 닫았을 때 표시 간격이 이전과 같은 범위다(플레이 화면까지 입력 스크립트 3회). 미발견 주소 dispatch 0건, 크래시 0건이다.
3. MSAA와 내부 배율을 켠 상태에서 render-to-texture를 쓰는 화면(곡 선택 등)이 깨지지 않는다(프레임 덤프).
4. 소프트웨어 렌더러, `--headless`, 게임 데이터 없는 구성이 이전처럼 동작하고 빌드된다.
5. probe: 설정 파일 읽기·쓰기(알 수 없는 키, 잘못된 값, 쓰기 실패 시 대체 경로)와 단축키 해석(Alt·Ctrl 조합이 게임 입력으로 새지 않음)은 창 없이 검사한다. 실패하면 창 없이 끝난다.
6. Win64 Debug/Release(Visual Studio 생성기 포함)와 Linux x64 빌드·CTest(repsp, reDMP1).
7. 사용자가 창 모드에서 메뉴, 옵션, 단축키를 확인한다(사용자 확인).

## 6. 기록

# Design: in-game UI (Dear ImGui), settings, window title and FPS, window shortcuts (issue #47, repsp #48)

## 1. Requirements

* **User request (2026-11-18)**: bring over these features from reCT3 and rexbox.
  1. The Dear ImGui in-game UI and settings: everything that is feasible, including the FPS graph and graphics options.
  2. The window title format with FPS, window size shortcuts, and fullscreen toggling (mouse click included).
* **User decisions (2026-11-18)**:
  * Graphics options: rendering resolution, window size, fullscreen and VSync as the base, plus aspect ratio, MSAA, texture filtering and output filter.
  * The in-game UI works with the OpenGL renderer only. With the software renderer only the title and shortcuts work.
  * Window size shortcuts are Alt+1..6 (1x..6x of 480x272).
  * A gamepad combo toggles the menu.
* **Reference implementation**: the reviewer puts copies in `%TEMP%\redmp1-build\borrow\`; they are not committed.
  * rexbox `include/rexbox/platform/overlay.h`, `src/platform/sdl/overlay_sdl.cpp`, `src/platform/sdl/display_sdl.cpp`
  * reCT3 `src/app/settings.{h,cpp}`, `settings_ui.{h,cpp}`, `main.cpp`
  * These repositories belong to the same organisation, so structure and code may be taken. Names and namespaces become repsp/reDMP1's.

## 2. Split

* **repsp (platform, game-independent)**:
  * the overlay contract and ImGui lifetime;
  * the title and FPS;
  * shortcuts;
  * the gamepad combo, and withholding game input while the menu is open;
  * display options (aspect, output filter, VSync, fullscreen, window scale);
  * GL backend options (rendering scale, MSAA, texture filtering);
  * stats sources (presented FPS, process memory, GPU memory).
* **reDMP1 (app)**: the settings file (`redmp1.ini`), the menu's content (tabs and widgets), the stats window, and the precedence between command-line options and the file.
* No game name or game information goes into repsp. The app sets the title's leading part.

## 3. repsp

### 3.1 Dear ImGui
* `third_party/imgui` (v1.93.0, MIT, the same commit as rexbox) is a submodule. The reviewer committed it.
* Build an `imgui` static library: the core plus `backends/imgui_impl_sdl3.cpp` and `imgui_impl_opengl3.cpp`. Record the licence in `THIRD_PARTY_NOTICES.md`.
* The app includes `imgui.h` itself to draw widgets, so the include path must be public.

### 3.2 Overlay contract (`include/repsp/platform/overlay.h`)
* The same shape as rexbox's:
  * `SetOverlayBuilder(std::function<void()>)` runs on every present, between `NewFrame` and `Render`.
  * `RenderOverlay()` is called by the platform on the UI thread (which owns the GL context), just before presenting. GL state is restored afterwards.
  * `OverlayVisible()` / `SetOverlayVisible()`.
* The menu toggles with Tab on the keyboard and LB+RB+Y on a gamepad (L+R+Triangle in the PSP mapping).
* While the menu is open, game input is withheld: the game sees nothing pressed and input goes to the overlay.
* ImGui is created only with the OpenGL renderer. With the software renderer the builder is never called.
* ImGui's `.ini` saving is off (`io.IniFilename = nullptr`); window placement belongs to the app's settings.
* The UI scale that follows the window size (OSD scale) follows rexbox.

### 3.3 Window title and FPS
* Format (as rexbox): `<app title> - OpenGL <major>.<minor> - FPS : <n.n>`. With the software renderer: `<app title> - Software - FPS : <n.n>`.
* FPS is computed from actual presents (frames shown through `sceDisplaySetFrameBuf`) over about a second.
* The title is changed only on the window's thread (for the same reason as rexbox issue #62).
* The app sets the leading part with `SetDisplayTitle()`.

### 3.4 Shortcuts and mouse

| Input | Action |
|---|---|
| Alt+1..6 | Window at 1x..6x of 480x272. Leaves fullscreen or a maximised window first. |
| Alt+Enter, left double click | Toggle fullscreen (a borderless window at desktop resolution; the display mode is never changed). |
| Ctrl+1..8 | Rendering resolution (internal scale 1..8). |
| Tab, LB+RB+Y | Toggle the menu. |

* Key presses with Alt or Ctrl held never reach the game. For example, Enter maps to START, so Alt+Enter must not leak as START.
* While the menu is open, ImGui receives double clicks. Only a double click outside the menu windows toggles fullscreen.

### 3.5 Display and GL options (changeable at run time)
* **Window scale** (1..6), **fullscreen**, and **VSync** (on/off; adaptive where available).
* **Aspect ratio**: keep the original aspect (letterbox) / stretch to the window / integer scales only (the rest black).
* **Output filter**: nearest / linear, used when stretching the final picture to the window.
* **Rendering resolution**: internal scale 1..8, the same value as the existing `--scale` and `SetInternalScale`.
* **MSAA**: off / 2x / 4x / 8x on GL render targets. An unsupported value falls back to the largest supported one. Where render targets are read back as textures (render-to-texture), the resolve must be correct.
* **Texture filtering**: original (as the game set it) / always linear / anisotropic 2x..16x (within the supported range).
* **Stats sources**: presented FPS, process memory (working set), and GPU memory (when the driver reports it; otherwise the sum of textures and targets this HLE created).

## 4. reDMP1

### 4.1 Settings file
* Same rules as reCT3: `redmp1.ini` next to the executable, or the user's settings folder when that folder is not writable.
* Unknown keys and malformed values keep the defaults. Saving goes through a temporary file.
* Entries: window scale, fullscreen, VSync, aspect ratio, output filter, rendering resolution, MSAA, texture filtering, the stats window's sections (FPS, memory, GPU memory) and its position.
* **Precedence**: command-line options (`--scale`, `--renderer`, ...) beat the file. A value set on the command line applies to that run only and is not written to the file. Changes made in the menu are saved to the file.

### 4.2 Settings menu (`src/app/` or the existing app directory)
* **Info**: version, build time, platform and configuration, commit, game (its game ID and title, not the disc image name), renderer and GL information, memory.
* **Graphics**: the options of 3.5 and the stats window sections. Values that do not apply at once show "applying" the way reCT3's Tracked values do.
* **Input**: the keyboard and gamepad mapping table (read-only) and the menu shortcuts.
* **Stats window**: FPS graph (0.5 s bins, as reCT3) and memory graphs. It can be dragged, and its position is saved.
* UI strings are in English, as in reCT3.

## 5. Measurement and verification

1. In windowed mode, check that:
   * Tab and LB+RB+Y open and close the menu;
   * the game reads no input while the menu is open;
   * each option applies at once (or as indicated) and persists across runs;
   * Alt+1..6, Alt+Enter, double click and Ctrl+1..8 work, and Alt+Enter does not leak as START;
   * the title's FPS matches actual presents.
2. Performance: with the menu closed, presentation intervals stay in the same range as before (three scripted runs to gameplay), with zero undiscovered-address dispatches and zero crashes.
3. With MSAA and an internal scale on, screens that use render-to-texture (song select and others) are not broken (frame dumps).
4. The software renderer, `--headless`, and the configuration without game data still work and build as before.
5. Probes, run without a window: settings file reading and writing (unknown keys, malformed values, the fallback path on a failed write), and shortcut interpretation (Alt and Ctrl combinations do not leak into game input). Failures exit without a dialog.
6. Win64 Debug/Release (including the Visual Studio generator) and Linux x64 builds and CTest (repsp and reDMP1).
7. The user checks the menu, options and shortcuts in windowed mode (the user's check).

* **reDMP1**: shortcuts, the menu and `redmp1.ini` in `README.md` (or the usage guide). The work log `docs/work-logs/20261118-i047-overlay.md` holds measurements and questions.
