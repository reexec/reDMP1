# 설계: 입력 — sceCtrl·sceDmac을 앱에 연결하고 첫 화면을 향해 진행 (issue #9)

## 1. 요구사항

* repsp의 sceCtrl·sceDmac HLE([repsp issue #9](https://github.com/reexec/repsp/issues/9))를 앱에 연결한다. 부팅이 멈추던 `sceCtrlSetSamplingMode` 너머로 진행한다.
* issue #7에서 게임은 첫 그리기 전에 멈췄다. 이번에는 이미 다루는 라이브러리 안에서는 계속 나아가, 그 밖의 라이브러리에서 처음 만나는 미구현 호출까지 간다(§2).
* 그 사이에 게임이 그린 것이 있으면 원본 게임의 사실로 `docs/analysis/first-frame.md`에 이어 적는다.

## 2. 진행 범위

* **이미 다루는 라이브러리**: 커널(ThreadMan, SysMem, IoFileMgr, ModuleMgr, LoadExec, Utils, Stdio, Kernel_Library, power, suspend, UMD), `sceGe_user`, `sceDisplay`, `sceCtrl`, `sceDmac`.
* 정지가 이 라이브러리 안의 미구현 함수나 결함(미구현 GE 명령·SIGNAL 동작, 그리지 않는 primitive 포함)이면, repsp submodule 브랜치에서 구현하거나 고치고 다시 실행한다. 추가한 함수는 probe로 검사하고, 커밋을 작업 로그에 적는다.
* 정지가 그 밖의 라이브러리(`sceAudio`, `sceAtrac3plus`, `sceSasCore`, `sceMpeg`, `sceUtility` 등)의 호출이면 거기서 멈추고 기록한다. 그 라이브러리들은 다음 task에서 설계한다.
* 설계 판단이 필요한 결함(스케줄러 의미 변경, 계약 변경 등)은 고치지 말고 작업 로그의 질문으로 올린다.

## 3. 실행

* `redmp1 roms`는 키보드와 게임패드 입력을 받는다(매핑은 repsp 설계 §4, `docs/guides/running-and-tracing.md`에 적는다).
* `--headless`는 중립 입력으로 돈다(CTest, CI).
* 정지 보고에 ctrl 통계(읽은 샘플 수, 모드)를 더한다.

## 4. 기록 (`docs/analysis/first-frame.md`에 이어서)

* `sceCtrl` 초기화 인자(주기, 모드)와 읽는 방식(한 번에 읽는 샘플 수, 호출 위치의 스레드).
* 정지까지의 HLE 순서: 새로 만드는 스레드, 여는 파일(원본 디스크 안의 경로), vblank 대기.
* 그린 것이 있으면: 리스트·primitive 통계, 쓴 텍스처 형식, 화면 내용의 글 서술. 이미지는 저장소에 넣지 않는다.
* 다음 정지 NID와 이름.
* 원본 게임의 사실만 적는다. 사용자 덤프의 위치나 이름은 적지 않는다.

## 5. 이번 task의 검증

1. 로컬: `redmp1 roms --headless`가 §2의 범위 밖 라이브러리의 미구현 NID에서 정지 분류 (a)로 멈춘다. 디스패치 미스, 교착이 없다.
2. 로컬: 프레임이 표시됐으면 프레임 덤프를 남기고 위치를 작업 로그에 적는다(리뷰어가 확인; 덤프는 커밋하지 않는다).
3. 로컬: 3회 실행의 HLE 추적을 비교한다. 다르면 원인(vblank 대기 횟수, 시각 의존 분기)을 분석해 기록한다.
4. CTest `app_boot`를 새 정지 지점으로 갱신한다.
5. Win64 Debug/Release와 Linux x64 빌드·CTest, CI 통과. 게임 데이터가 없는 구성(`REDMP1_HAVE_RECOMP=0`)도 경고 없이 빌드돼야 한다(issue #7의 CI 실패).

# Design: input — wiring sceCtrl and sceDmac into the app and running on toward the first picture (issue #9)

## 1. Requirements

Wire repsp's sceCtrl and sceDmac HLE ([repsp issue #9](https://github.com/reexec/repsp/issues/9)) into the app and run past `sceCtrlSetSamplingMode`, where the boot stopped. In issue #7 the game stopped before its first draw; this time the run keeps going inside the libraries already covered, up to the first unimplemented call in any other library (§2). Whatever the game draws on the way is recorded as facts about the original game, continuing `docs/analysis/first-frame.md`.

## 2. How far to go

Libraries already covered: the kernel (ThreadMan, SysMem, IoFileMgr, ModuleMgr, LoadExec, Utils, Stdio, Kernel_Library, power, suspend, UMD), `sceGe_user`, `sceDisplay`, `sceCtrl` and `sceDmac`. A stop at an unimplemented function or a defect inside these (including an undecoded GE command, a SIGNAL behaviour or an undrawn primitive) is implemented or fixed on the repsp submodule branch and the run repeated; added functions get probes and their commits go to the work log. A stop at a call into any other library (`sceAudio`, `sceAtrac3plus`, `sceSasCore`, `sceMpeg`, `sceUtility` and so on) ends the task and is recorded; those libraries are designed in later tasks. A defect that needs a design decision (scheduler semantics, a contract change) is not fixed but raised as a question in the work log.

## 3. Running

`redmp1 roms` takes keyboard and gamepad input (the mapping of repsp design §4, documented in `docs/guides/running-and-tracing.md`); `--headless` runs with neutral input (CTest, CI). The stop report gains ctrl statistics (samples read, mode).

## 4. Record (continuing `docs/analysis/first-frame.md`)

The `sceCtrl` setup arguments (cycle, mode) and how it is read (samples per read, the calling thread); the HLE order up to the stop, with threads created, files opened (paths inside the original disc) and vblank waits; if anything is drawn, list and primitive statistics, texture formats used and a written description of the picture, with no image in the repository; the next stop NID and its name. Facts about the original game only — no location or name of the user's dump.

## 5. Verification for this task

1. Local: `redmp1 roms --headless` stops, class (a), at an unimplemented NID of a library outside §2; no dispatch miss or deadlock.
2. Local: if a frame was presented, frame dumps are kept and their location goes to the work log (checked by the reviewer; never committed).
3. Local: the HLE traces of three runs are compared; any difference is analyzed (the number of vblank waits, branches on time) and recorded.
4. CTest `app_boot` is updated to the new stop point.
5. Win64 Debug/Release and Linux x64 builds and CTest, and CI, pass; the configuration without game data (`REDMP1_HAVE_RECOMP=0`) must build without warnings too (the CI failure of issue #7).
