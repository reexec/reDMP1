# 설계: 오디오 — sceAudio·sceSasCore·sceAtrac3plus를 앱에 연결하고 첫 화면을 향해 진행 (issue #11)

## 1. 요구사항

* repsp의 오디오 HLE([repsp issue #11](https://github.com/reexec/repsp/issues/11))를 앱에 연결한다. 부팅이 멈추던 `sceAudioChReserve` 너머로 진행한다.
* issue #9와 같은 방식으로, 이미 다루는 라이브러리 안에서는 계속 나아가 그 밖의 라이브러리에서 처음 만나는 미구현 호출까지 간다(§2).
* **사용자 결정(issue #11)**: ATRAC3plus는 지금은 무음으로 디코딩한다. 디코더 선택은 소리가 필요해질 때 정한다.
* 게임의 오디오 구성과, 그 사이에 그린 것을 원본 게임의 사실로 `docs/analysis/`에 기록한다.

## 2. 진행 범위

* **이미 다루는 라이브러리**: 커널(ThreadMan, SysMem, IoFileMgr, ModuleMgr, LoadExec, Utils, Stdio, Kernel_Library, power, suspend, UMD), `sceGe_user`, `sceDisplay`, `sceCtrl`, `sceDmac`, `sceAudio`, `sceSasCore`, `sceAtrac3plus`.
* 정지가 이 라이브러리 안의 미구현 함수나 결함(미구현 GE 명령·SIGNAL 동작, 그리지 않는 primitive 포함)이면, repsp submodule 브랜치에서 구현하거나 고치고 다시 실행한다. 추가한 함수는 probe로 검사하고, 커밋을 작업 로그에 적는다.
* 정지가 그 밖의 라이브러리(`sceMpeg`, `sceUtility`)의 호출이면 거기서 멈추고 기록한다.
* 설계 판단이 필요한 결함(스케줄러 의미 변경, 계약 변경, 디코더 문제 등)은 고치지 말고 작업 로그의 질문으로 올린다.
* 정지 없이 계속 도는 상태(예: 타이틀 화면에서 입력 대기)에 이르면, headless 실행을 정해진 vblank 수에서 끝내는 앱 옵션(`--max-vblanks <n>`)을 더해 그 시점의 상태를 보고하게 한다. 이 종료는 새 정지 분류(예: (e) vblank 한도)로 구분한다.

## 3. 실행

* 창 모드에서는 소리가 장치로 나간다(ATRAC 음악은 무음, SAS 효과음은 실제 소리). `--headless`는 dummy 오디오 장치로 같은 속도로 돈다.
* 정지 보고에 오디오 통계를 더한다: 채널별 출력, SAS voice 사용, ATRAC ID 수와 디코딩 프레임 수, "ATRAC decode: silent".

## 4. 기록

* `docs/analysis/audio.md`(새 파일): 채널 예약(샘플 수, 형식), 오디오 스레드의 구성(이름, 우선순위, 출력 루프), SAS 초기화 인자(grain, voice 수)와 쓰는 기능, ATRAC 데이터의 형식(코덱, 채널, 샘플레이트, 블록 크기, 루프 유무)과 스트리밍 방식(전체 로드인지 스트림인지), 원본 디스크 안에서 오디오 데이터가 오는 위치.
* `docs/analysis/first-frame.md`에 이어서: 정지까지의 HLE 순서, 그린 것이 있으면 리스트·primitive 통계와 화면 내용의 글 서술(이미지는 저장소에 넣지 않는다), 다음 정지 NID와 이름.
* 원본 게임의 사실만 적는다. 사용자 덤프의 위치나 이름은 적지 않는다.

## 5. 이번 task의 검증

1. 로컬: `redmp1 roms --headless`가 §2의 범위 밖 라이브러리의 미구현 NID에서 정지 분류 (a)로 멈추거나, vblank 한도로 끝난다. 디스패치 미스, 교착이 없다.
2. 로컬: 프레임이 표시됐으면 프레임 덤프를 남기고 위치를 작업 로그에 적는다(리뷰어가 확인; 덤프는 커밋하지 않는다).
3. 로컬: 3회 실행의 HLE 추적을 비교한다. 오디오 대기가 호스트 시각에 묶이므로 스레드 사이의 호출 순서가 달라질 수 있다. 다르면 원인을 분석해 기록한다.
4. CTest `app_boot`를 새 종료 지점으로 갱신한다.
5. Win64 Debug/Release와 Linux x64 빌드·CTest, CI 통과. 게임 데이터가 없는 구성(`REDMP1_HAVE_RECOMP=0`)도 경고 없이 빌드된다.

# Design: audio — wiring sceAudio, sceSasCore and sceAtrac3plus into the app and running on toward the first picture (issue #11)

## 1. Requirements

Wire repsp's audio HLE ([repsp issue #11](https://github.com/reexec/repsp/issues/11)) into the app and run past `sceAudioChReserve`, where the boot stopped. As in issue #9, the run keeps going inside the libraries already covered, up to the first unimplemented call in any other library (§2). **User decision (issue #11)**: ATRAC3plus decodes to silence for now; the decoder is chosen when sound is needed. The game's audio setup and whatever it draws on the way are recorded in `docs/analysis/` as facts about the original game.

## 2. How far to go

Libraries already covered: the kernel (ThreadMan, SysMem, IoFileMgr, ModuleMgr, LoadExec, Utils, Stdio, Kernel_Library, power, suspend, UMD), `sceGe_user`, `sceDisplay`, `sceCtrl`, `sceDmac`, `sceAudio`, `sceSasCore` and `sceAtrac3plus`. A stop at an unimplemented function or a defect inside these (including an undecoded GE command, a SIGNAL behaviour or an undrawn primitive) is implemented or fixed on the repsp submodule branch and the run repeated; added functions get probes and their commits go to the work log. A stop at a call into any other library (`sceMpeg`, `sceUtility`) ends the task and is recorded. A defect that needs a design decision (scheduler semantics, a contract change, a decoder problem) is not fixed but raised as a question in the work log. If the run reaches a state that keeps going without a stop (for example a title screen waiting for input), an app option that ends a headless run after a given number of vblanks (`--max-vblanks <n>`) is added so the state at that point is reported; that end is its own stop class (for example (e), vblank limit).

## 3. Running

In a window, sound goes to the device (ATRAC music is silent, SAS effects are real); `--headless` runs at the same pace on the dummy audio device. The stop report gains audio statistics: output per channel, SAS voices used, the number of ATRAC IDs and decoded frames, and "ATRAC decode: silent".

## 4. Record

`docs/analysis/audio.md` (new): channel reservations (sample counts, formats), the audio threads (names, priorities, output loops), the SAS setup arguments (grain, voices) and features used, the format of the ATRAC data (codec, channels, sample rate, block size, loops) and how it is streamed (loaded whole or streamed), and where on the original disc the audio data comes from. Continuing `docs/analysis/first-frame.md`: the HLE order up to the stop; if anything is drawn, list and primitive statistics and a written description of the picture (no image in the repository); the next stop NID and its name. Facts about the original game only — no location or name of the user's dump.

## 5. Verification for this task

1. Local: `redmp1 roms --headless` stops, class (a), at an unimplemented NID of a library outside §2, or ends at the vblank limit; no dispatch miss or deadlock.
2. Local: if a frame was presented, frame dumps are kept and their location goes to the work log (checked by the reviewer; never committed).
3. Local: the HLE traces of three runs are compared; audio waits follow host time, so the call order between threads may differ, and any difference is analyzed and recorded.
4. CTest `app_boot` is updated to the new end point.
5. Win64 Debug/Release and Linux x64 builds and CTest, and CI, pass; the configuration without game data (`REDMP1_HAVE_RECOMP=0`) builds without warnings.
