# 설계: 단축키를 reCT3와 같게, 게임 종료 단축키 표시 (issue #58, repsp #61)

## 1. 요구사항

* 사용자 요청(2026-11-21):
  * OSD에 게임 종료 단축키를 reCT3와 같게 보인다.
  * 모든 단축키를 reCT3와 같게 한다.
* **reCT3(rexbox 오버레이)의 동작**:
  * 메뉴: 게임패드 LT+RT+Y. 누르는 순간 토글한다. 트리거는 절반을 넘으면 눌린 것으로 본다.
  * 종료: LT+RT를 누른 채 L3+R3(두 스틱 클릭)를 1초 누르면 앱 종료를 요청한다. 한 번 누르는 동안 한 번만 요청한다.
  * 메뉴의 안내 문구: "Gamepad: LT+RT+Y menu, LT+RT+L3+R3 held 1 s quits."
* **reDMP1의 지금 상태**:
  * 메뉴는 LB+RB+Y다.
  * 종료 조합은 없다.
  * 키보드 단축키(Tab, Alt+1~6, Alt+Enter·더블클릭, Ctrl+1~8)는 reCT3와 같은 방식이다. 창 배율 범위만 480x272에 맞춰 1~6이고, 그대로 둔다.
* LT/RT는 PSP 버튼에 연결돼 있지 않다(PSP L/R은 LB/RB). 그래서 LT+RT를 앞에 붙인 조합은 게임 입력과 겹치지 않는다.

## 2. 변경

### 2.1 repsp #61 (`src/platform/sdl/overlay_sdl.cpp`)
* 메뉴 조합을 **LT+RT+Y**로 바꾼다. 트리거 축이 16384를 넘으면 눌림이다.
* 종료 조합 **LT+RT+L3+R3를 1초**:
  * 처음 누른 뒤 1초가 지나면 한 번 종료를 요청한다.
  * 떼면 다시 잰다.
  * 요청은 창 닫기와 같은 경로로 간다(`RequestStop` 또는 지금 창 닫기가 쓰는 경로). 앱이 평소처럼 끝난다(세이브, `redmp1.ini`, 통계 출력 포함).
  * 로그를 한 줄 남긴다: `[overlay] quit requested (LT+RT+L3+R3)`
* **LT+RT가 눌린 동안**에는 Y, L3, R3를 게임 입력으로 보내지 않는다. 메뉴가 닫혀 있어도 마찬가지다. Y는 PSP 세모, L3/R3는 매핑에 따른다. 나머지 버튼은 그대로 보낸다.
* 종료 조합은 소프트웨어 렌더러(오버레이 없음)에서도 동작한다. 메뉴 조합은 지금처럼 OpenGL에서만 동작한다.

### 2.2 reDMP1 #58
* 메뉴 머리말을 "Tab (LT+RT+Y on a gamepad) closes this menu…"로 고친다.
* Input 탭의 단축키 표에 다음 두 행을 둔다.
  * "Tab / LT+RT+Y — Open / close settings menu"
  * "LT+RT+L3+R3 (hold 1 s) — Quit"
* reCT3처럼 Graphics 탭 끝에 안내 문구 한 줄을 둔다: `Shortcuts: Ctrl+1..8 resolution, Alt+Enter or double click fullscreen, Alt+1..6 window size. Gamepad: LT+RT+Y menu, LT+RT+L3+R3 held 1 s quits.`
* README의 단축키 설명을 고친다.

## 3. 검증

1. **probe**(창 없이, 결정적):
   * 단축키 해석을 SDL 없이 시험할 수 있게 상태 판정 함수로 나눈다(트리거 값·버튼 → 메뉴 토글·종료 요청·차단할 버튼).
   * 경우: LT+RT+Y 한 번에 토글 한 번, 1초 미만이면 종료하지 않음, 1초에 한 번, 계속 눌러도 한 번, LT+RT가 없으면 Y·L3·R3가 게임으로 감.
2. 게임(창 모드)에서 메뉴와 종료 조합이 동작한다. 종료 시 종료 코드가 정상이고 `redmp1.ini`가 저장된다.
3. Win64 Debug/Release(Visual Studio 생성기 포함)와 Linux x64 빌드·CTest(repsp, reDMP1).
4. 사용자가 게임패드로 확인한다(사용자 확인).

# Design: shortcuts as in reCT3, with the quit shortcut shown (issue #58, repsp #61)

## 1. Requirements

* **User request (2026-11-21)**:
  * Show the quit shortcut in the OSD, as reCT3 does.
  * Make every shortcut the same as reCT3.
* **reCT3 (rexbox overlay) behaviour**:
  * Menu: gamepad LT+RT+Y, toggling as it goes down. A trigger counts once past half way.
  * Quit: LT+RT with L3+R3 (both stick clicks) held for one second requests the app to quit, once per hold.
  * Menu text: "Gamepad: LT+RT+Y menu, LT+RT+L3+R3 held 1 s quits."
* **reDMP1 today**:
  * The menu combo is LB+RB+Y.
  * There is no quit combo.
  * The keyboard shortcuts (Tab, Alt+1..6, Alt+Enter or double click, Ctrl+1..8) already work as in reCT3. Only the window-scale range is 1..6, to suit 480x272, and it stays.
* LT/RT are not mapped to PSP buttons (PSP L/R are on LB/RB), so combos starting with LT+RT never collide with game input.

## 2. Changes

### 2.1 repsp #61 (`src/platform/sdl/overlay_sdl.cpp`)
* The menu combo becomes **LT+RT+Y**. A trigger counts as down past axis value 16384.
* **Quit combo, LT+RT+L3+R3 held 1 s**:
  * One second after first pressed, one quit request.
  * Releasing restarts the count.
  * The request takes the same path as closing the window (`RequestStop`, or whatever window close uses today), so the app ends normally: save, `redmp1.ini`, stats output.
  * One log line: `[overlay] quit requested (LT+RT+L3+R3)`.
* **While LT+RT are down**, Y, L3 and R3 are withheld from game input, even with the menu closed. Y is PSP triangle; L3/R3 follow the mapping. Other buttons pass as usual.
* The quit combo also works with the software renderer (no overlay). The menu combo stays OpenGL-only, as today.

### 2.2 reDMP1 #58
* The menu header becomes "Tab (LT+RT+Y on a gamepad) closes this menu…".
* The Input tab's shortcut table lists:
  * "Tab / LT+RT+Y — Open / close settings menu";
  * "LT+RT+L3+R3 (hold 1 s) — Quit".
* As in reCT3, one line at the end of the Graphics tab: `Shortcuts: Ctrl+1..8 resolution, Alt+Enter or double click fullscreen, Alt+1..6 window size. Gamepad: LT+RT+Y menu, LT+RT+L3+R3 held 1 s quits.`
* The README's shortcut description follows.

## 3. Verification

1. **Probe** (no window, deterministic):
   * Split shortcut interpretation into a state function testable without SDL: trigger values and buttons in; menu toggle, quit request and withheld buttons out.
   * Cases: LT+RT+Y toggles once; under one second does not quit; one second quits once; holding longer still quits once; without LT+RT, Y, L3 and R3 reach the game.
2. In the game (windowed), the menu and quit combos work. Quitting gives a normal exit code and saves `redmp1.ini`.
3. Win64 Debug/Release (including the Visual Studio generator) and Linux x64, build and CTest, for repsp and reDMP1.
4. The user checks with a gamepad (the user's check).
