# 설계: psprecomp upstream v0.6.0으로 이동 (issue #62)

## 1. 배경

upstream psprecomp v0.6.0(`14749c1`)에 다음이 들어갔다.

* 이 저장소의 로컬 패치가 upstream에 들어간 것:

  | 로컬 패치 | upstream |
  |---|---|
  | 0001 (`--base`, `relocate`) | #36 |
  | 0003 (링크하는 `jalr` 뒤를 이어 감) | #31(다른 기여자, 같은 수정) |
  | 0004 (자기 본문 주소로 가는 `j`는 goto) | #35 |
  | 0006 (루프 훅) | #38 |

* 생성 코드를 바꾸는 다른 변경은 #32 하나다. 게스트 호출의 복귀 지점 프레임을 생성 본문이 아니라 런타임 함수가 맡는다.
  * 바뀌기 전에는 본문이 `PSP_CALL_BEGIN`에서 `psp_frame`을 쌓고 `PSP_CALL_END`에서 내렸다.
  * 바뀐 뒤에는 `psp_call_guest_fn(fn, ret)`와 `psp_call_guest_addr(addr, ret)`가 쌓고 내린다. 본문의 `PSP_CALL_END`는 unwind가 남아 있을 때 돌아가기만 한다.
* `emit --hints`는 선택 사항이라 쓰지 않는다. 나머지(HLE, 창, 모듈 로더, VFPU)는 upstream 런타임(`src/`)의 일이고, 이 저장소는 자기 런타임(`src/recomp_abi/`, repsp)을 쓰므로 영향이 없다.
* 0005(`--trampoline`, #37)는 아직 upstream에 없다. v0.6.0 위로 rebase했다(fork 브랜치 `emit-trampoline`, `d9278d2`).
  * trampoline 모드에서도 게스트 호출은 #32 방식으로 낸다.
  * `psp_call_guest_fn`이 호출 대상을 `psp_run`으로 실행해, 대상이 남긴 tail 이동을 이어서 처리한다.

## 2. 측정: 다시 생성한 코드의 차이

v0.6.0과 rebase한 0005로 만든 lifter를 지금과 같은 인자(`--base 0x08804000 --trampoline`)로 BOOT.BIN에 돌렸다. 그 출력을 지금 생성 코드와 비교했다. 주소를 지우고 줄 빈도를 비교했으며, 줄 순서는 보지 않았다.

| 지금 | 다시 생성 | 수 |
|---|---|---|
| `psp_run(psp_func_X);` | `psp_call_guest_fn(psp_func_X, ret);` | 10,933 |
| `psp_import_X();` | `psp_call_guest_fn(psp_import_X, ret);` | 699 |
| `psp_dispatch(_t);` | `psp_call_guest_addr(_t, ret);` | 400 |
| `psp_dispatch(X);  /* not discovered */` | `psp_call_guest_addr(X, ret);  /* not discovered */` | 10 |
| 헤더의 `PSP_CALL_BEGIN`/`PSP_CALL_END`(프레임을 쌓음) | 프레임 없이 unwind만 전달 | 1 |

이 밖의 생성 코드는 같다. 헤더 주석 몇 줄(루프 훅 설명 등)만 다르다.

## 3. 변경

1. **submodule**: `third_party/psprecomp`을 `14749c1`(v0.6.0)로 올린다.
2. **로컬 패치**:
   * 0001, 0003, 0004, 0006을 지운다.
   * 0005는 `d9278d2`에서 다시 만든다: `git format-patch -1 d9278d2 --stdout -- tools/allegrexrecomp`.
   * `CMakeLists.txt`의 패치 목록과 `patches/psprecomp/README.md`(기준 커밋, upstream 상태 표, 패치 설명)를 맞춘다.
3. **ABI 어댑터**(`src/recomp_abi/dispatch.c`): 두 함수를 추가한다. 선언은 `psprecomp/dispatch.h`에 있다.

   ```c
   void psp_call_guest_fn(psp_fn_t fn, uint32_t ret) {
       psp_frame f = { ret, psp_cpu.frame };
       psp_cpu.frame = &f;
       psp_run(fn);                  /* fn과, fn이 남긴 tail 사슬 */
       psp_cpu.frame = f.prev;
       if (psp_cpu.unwind == ret) psp_cpu.unwind = 0;
   }
   /* psp_call_guest_addr: psp_run(fn) 대신 psp_dispatch(addr) */
   ```

   * upstream처럼 인라인되지 않게 한다. 본문 안에 프레임 주소가 생기면 그 본문의 sibling call 최적화가 막히기 때문이다.
   * `README.md`의 표에 두 함수를 더한다.
4. **다시 생성**: 새로 빌드한 lifter로 `scripts/recomp/regenerate.py`를 돌린다. 생성 코드는 커밋하지 않는다.
5. **probe**(`tests/recomp_abi_probe.cpp`):
   * `psp_call_guest_fn`이 대상이 남긴 tail 사슬을 끝까지 실행한다.
   * 돌아온 뒤 프레임이 원래대로다.
   * 자기 복귀 지점을 겨눈 unwind는 지우고, 더 바깥을 겨눈 unwind는 남긴다.
   * `psp_call_guest_addr`도 같은 동작을 하고, 미등록 주소는 miss로 보고한다.

## 4. 검증

1. Win64 Release(Visual Studio 생성기), Win64 Ninja Debug/Release, Linux x64 Debug/Release 빌드와 CTest가 통과한다.
2. 다시 생성한 코드의 차이가 §2와 같다.
3. 게임(Release): 입력 스크립트와 `--autoplay`로 한 곡을 끝까지 돌린다.
   * STAGE CLEARED이고 BREAK가 0이다.
   * 미발견 주소 dispatch가 0이다.
   * 결과 화면까지 간다.
4. 게임(Debug, 생성 코드 최적화 없음): 같은 곡을 끝까지 돌린다. 스택 넘침이 없어야 한다.
5. 성능: 같은 장면에서 v0.0.30과 FPS를 비교한다(Stats 창). 호출마다 함수 하나를 더 거치므로 확인한다.
6. 사용자 확인.

# Design: move psprecomp to upstream v0.6.0 (issue #62)

## 1. Background

Upstream psprecomp v0.6.0 (`14749c1`) brings the following.

* Local patches of this repository, now upstream:

  | Local patch | Upstream |
  |---|---|
  | 0001 (`--base`, `relocate`) | #36 |
  | 0003 (continue after a linking `jalr`) | #31 (another contributor, same fix) |
  | 0004 (a `j` into the body's own addresses is a goto) | #35 |
  | 0006 (loop hook) | #38 |

* The only other change to generated code is #32. A guest call's return-site frame is owned by runtime functions, not by the emitted body.
  * Before, the body pushed a `psp_frame` in `PSP_CALL_BEGIN` and popped it in `PSP_CALL_END`.
  * Now `psp_call_guest_fn(fn, ret)` and `psp_call_guest_addr(addr, ret)` push and pop it. The body's `PSP_CALL_END` only returns while an unwind is pending.
* `emit --hints` is optional and not used. The rest (HLE, window, module loader, VFPU) belongs to upstream's runtime (`src/`); this repository has its own runtime (`src/recomp_abi/`, repsp), so it is unaffected.
* 0005 (`--trampoline`, #37) is not upstream yet. It is rebased onto v0.6.0 (fork branch `emit-trampoline`, `d9278d2`).
  * In trampoline mode, guest calls are emitted the #32 way too.
  * `psp_call_guest_fn` runs the callee through `psp_run`, so the tail transfers the callee leaves are carried on.

## 2. Measured: the regenerated code's difference

A lifter built from v0.6.0 plus the rebased 0005 was run on BOOT.BIN with the current arguments (`--base 0x08804000 --trampoline`). Its output was compared with the current generated code: addresses were blanked and line frequencies compared, ignoring line order.

| Now | Regenerated | Count |
|---|---|---|
| `psp_run(psp_func_X);` | `psp_call_guest_fn(psp_func_X, ret);` | 10,933 |
| `psp_import_X();` | `psp_call_guest_fn(psp_import_X, ret);` | 699 |
| `psp_dispatch(_t);` | `psp_call_guest_addr(_t, ret);` | 400 |
| `psp_dispatch(X);  /* not discovered */` | `psp_call_guest_addr(X, ret);  /* not discovered */` | 10 |
| The header's `PSP_CALL_BEGIN`/`PSP_CALL_END` (push a frame) | No frame; only pass an unwind on | 1 |

Everything else in the generated code is the same, apart from a few header comment lines (the loop hook's description among them).

## 3. Changes

1. **Submodule**: move `third_party/psprecomp` to `14749c1` (v0.6.0).
2. **Local patches**:
   * Delete 0001, 0003, 0004 and 0006.
   * Regenerate 0005 from `d9278d2`: `git format-patch -1 d9278d2 --stdout -- tools/allegrexrecomp`.
   * Update the patch list in `CMakeLists.txt` and `patches/psprecomp/README.md` (base commit, upstream status table, patch descriptions).
3. **ABI adapter** (`src/recomp_abi/dispatch.c`): add two functions, declared in `psprecomp/dispatch.h`.

   ```c
   void psp_call_guest_fn(psp_fn_t fn, uint32_t ret) {
       psp_frame f = { ret, psp_cpu.frame };
       psp_cpu.frame = &f;
       psp_run(fn);                  /* fn and the tail chain it leaves */
       psp_cpu.frame = f.prev;
       if (psp_cpu.unwind == ret) psp_cpu.unwind = 0;
   }
   /* psp_call_guest_addr: psp_dispatch(addr) in place of psp_run(fn) */
   ```

   * As upstream does, keep them from being inlined: a frame address inside a body blocks that body's sibling-call optimization.
   * Add both to the table in `README.md`.
4. **Regenerate**: run `scripts/recomp/regenerate.py` with the newly built lifter. Generated code is not committed.
5. **Probe** (`tests/recomp_abi_probe.cpp`):
   * `psp_call_guest_fn` runs the tail chain the callee leaves to its end.
   * The frame is restored after it returns.
   * An unwind aimed at its own return site is cleared; one aimed further out is kept.
   * `psp_call_guest_addr` behaves the same, and reports an unregistered address as a miss.

## 4. Verification

1. Build and CTest pass on Win64 Release (Visual Studio generator), Win64 Ninja Debug/Release and Linux x64 Debug/Release.
2. The regenerated code differs as in §2.
3. Game (Release): play one song to the end with the input script and `--autoplay`.
   * STAGE CLEARED, with BREAK 0.
   * No unresolved-address dispatches.
   * The run reaches the result screen.
4. Game (Debug, generated code unoptimized): the same song to the end, with no stack overflow.
5. Performance: compare FPS with v0.0.30 on the same scene (Stats window), since every call now goes through one more function.
6. User check.
