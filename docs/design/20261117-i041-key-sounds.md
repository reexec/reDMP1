# 설계: 키음 (issue #41)

## 1. 요구사항

* 사용자 보고(2026-11-17): 플레이 중 키음이 원래의 비트 깊이나 샘플링레이트대로 나지 않는 것처럼 들린다. 같은 곡을 다른 에뮬레이터로 들으면 정상이다(사용자 녹화, 커밋하지 않음).
* **리뷰어의 녹화 비교**(곡 시작에 맞춤, 상관 0.97):
  * 6 kHz 아래는 두 녹화가 0.1 dB 이내로 같다. 음악(ATRAC3plus, 채널 1)은 정상이다.
  * reDMP1 녹화에만 키음이 나는 순간에 짧은 광대역 잡음이 있다. 이 잡음은 녹화 인코더의 차단 주파수인 21 kHz까지 닿고, 20.5~21 kHz에서 최대 +40 dB다.
  * 그 구간에는 피크의 약 60%에 이르는 표본 사이의 급격한 단차가 있다.
  * 즉 SAS(`sceSasCore`, 채널 2) 출력에 클릭이나 잡음이 있다.
* 앞서 미뤄 둔 "mode select에서 효과음이 느리게 들림"도 같은 SAS 경로다. 원인이 같을 수 있으므로 함께 확인한다.
* 목표: SAS 출력이 하드웨어처럼 되게 한다. 고치는 곳은 repsp의 `hle/sascore`이고, 게임과 무관한 HLE 동작으로 고친다.

## 2. 조사 (먼저)

1. **재현**: 플레이 화면에서 레인 버튼을 여러 번 누르는 입력 스크립트를 `%TEMP%` 아래에 만든다(커밋하지 않는다). 그 스크립트로 `REPSP_SAS_TRACE=1`, `REPSP_AUDIO_DUMP`(SAS 출력 WAV), HLE 추적을 켜고 실행한다.
2. **호출 목록**: 키음 구간에서 SAS 호출과 인자를 모두 정리한다. 대상은 `SetVoice*`(PCM·ATRAC 변형 포함), `SetPitch`, `SetADSR`/`SetSimpleADSR`/`SetADSRMode`, `SetVolume`, `SetKeyOn`/`SetKeyOff`, `GetEndFlag`, `GetEnvelopeHeight`, `SetNoise`, `SetTrianglarWave`, `SetSL`, `RevParam`이다. 구현되지 않은 NID가 불리는지(미구현 호출 로그)도 확인한다.
3. **어긋남 찾기**: SAS 덤프의 키음 하나를 같은 음원(게스트 메모리의 VAG 또는 PCM)을 명세대로 디코드한 기대 파형과 비교한다. 클릭과 잡음이 어디서 생기는지 좁힌다. 후보는 다음과 같다.
   * 키 온·오프 때 엔벌로프의 급변(즉시 0, 즉시 최대)
   * 같은 보이스를 다시 켤 때 이전 소리를 끊는 방식
   * 루프·끝 블록 처리
   * 피치 보간
   * 여러 보이스 합성의 포화(클리핑)
   * 미구현 함수
   * 볼륨과 엔벌로프의 비트 폭과 단위
   * 샘플 형식(VAG가 아닌 PCM 보이스)
4. **mode select 효과음**: 같은 방법으로 재생 속도(덤프 길이와 기대 길이)를 확인한다.
5. **근거로 쓸 수 있는 자료**: 공개 문서(PSPSDK 헤더, uOFW, psx-spx의 SPU ADPCM·ADSR)와 사용자 녹화(블랙박스 비교)만 쓴다. PPSSPP 등 GPL 구현 코드는 보지 않는다. 문서에 근거가 없는 동작은 **추정**으로 표시한다.

## 3. 수정

* 2에서 찾은 원인을 repsp `hle/sascore`에서 고친다. 게임별 분기를 두지 않는다.
* repsp 테스트(probe)에 원인을 재현하는 합성 입력(손으로 만든 VAG 블록과 키 온·오프 순서)을 넣는다. 고치기 전에는 실패하고, 고친 뒤에는 통과해야 한다.
* 원인이 여러 개면 각각 따로 커밋한다.

## 4. 검증

1. 키음 구간의 SAS 덤프에서, 고치기 전과 뒤의 광대역 잡음과 단차를 같은 지표로 비교한다. 지표는 20 kHz 근처 에너지와 최대 단차다(리뷰어가 쓴 방법을 작업 로그에 적는다).
2. 플레이 화면까지 입력 스크립트 실행 3회가 같은 화면에 이르고, 미발견 주소 dispatch 0건, 크래시 0건이다.
3. Win64 Debug/Release(Visual Studio 생성기 포함)와 Linux x64 빌드·CTest(repsp, reDMP1).
4. 사용자가 녹화와 같은 곡을 플레이해 키음과 mode select 효과음을 듣는다(사용자 확인).

## 5. 기록

* `docs/analysis/audio.md`: 키음 경로(사용하는 SAS 함수, 보이스 수, 음원 형식, 피치·ADSR·볼륨 값)를 원본에 대한 사실로 적는다. 사용자 파일 정보는 적지 않는다.
* repsp: 바뀐 HLE 동작과 근거. 작업 로그 `docs/work-logs/20261117-i041-key-sounds.md`에는 조사 결과, 측정표, 질문을 적는다.

# Design: key sounds (issue #41)

## 1. Requirements

**User report (2026-11-17)**: during play, key sounds do not sound right, as if not played at their original bit depth or sample rate. The same song in another emulator sounds right (user recordings, not committed).

**Reviewer's comparison of the recordings** (aligned on the song start, correlation 0.97):
- Below 6 kHz the two are within 0.1 dB, so the music (ATRAC3plus, channel 1) is fine.
- Only the reDMP1 recording has short broadband bursts at key-sound moments. They reach the recorder's 21 kHz cutoff and are up to +40 dB in 20.5-21 kHz.
- Those stretches have sample-to-sample steps of about 60% of the peak.
- So the SAS output (`sceSasCore`, channel 2) contains clicks or noise.

The earlier, deferred report of slow-sounding effects in mode select goes through the same SAS path and may share the cause, so it is checked too.

**Goal**: SAS output that behaves like the hardware, fixed in repsp's `hle/sascore` as game-independent HLE behaviour.

## 2. Investigation (first)

1. **Reproduce**: write an input script under `%TEMP%` (not committed) that presses the lane buttons repeatedly during gameplay. Run it with `REPSP_SAS_TRACE=1`, `REPSP_AUDIO_DUMP` (a WAV of SAS output) and HLE tracing.
2. **List the calls**: tabulate every SAS call and its arguments in the key-sound stretch. That covers `SetVoice*` (including the PCM and ATRAC variants), `SetPitch`, `SetADSR`/`SetSimpleADSR`/`SetADSRMode`, `SetVolume`, `SetKeyOn`/`SetKeyOff`, `GetEndFlag`, `GetEnvelopeHeight`, `SetNoise`, `SetTrianglarWave`, `SetSL` and `RevParam`. Also check for unimplemented NIDs (the unimplemented-call log).
3. **Find the divergence**: compare one key sound in the SAS dump with the expected waveform, decoded per the specification from the same source data (the VAG or PCM in guest memory). Narrow down where the clicks and noise come from. Candidates:
   - envelope jumps at key on/off (straight to zero or straight to full);
   - how a voice that is re-triggered cuts its previous sound;
   - loop and end-block handling;
   - pitch interpolation;
   - saturation when voices are summed (clipping);
   - unimplemented functions;
   - the bit width and units of volume and envelope;
   - sample format (PCM voices instead of VAG).
4. **Mode select effects**: check playback speed the same way, comparing the dump's length with the expected length.
5. **Allowed evidence**: public documents (PSPSDK headers, uOFW, psx-spx on SPU ADPCM and ADSR) and the user's recordings (black-box comparison) only. PPSSPP and other GPL implementation code is not read. Behaviour with no documentary basis is marked **inferred**.

## 3. Fix

- Fix what section 2 finds in repsp's `hle/sascore`, with no game-specific branches.
- Add a repsp probe with synthetic input (hand-built VAG blocks and a key on/off sequence) that reproduces the cause: it must fail before the fix and pass after.
- If there are several causes, commit each separately.

## 4. Verification

1. On the SAS dump of the key-sound stretch, compare broadband noise and steps before and after the fix with the same metrics: energy near 20 kHz and the largest step. Record the method in the work log.
2. Three scripted runs to gameplay reach the same screens, with zero undiscovered-address dispatches and zero crashes.
3. Win64 Debug/Release (including the Visual Studio generator) and Linux x64 builds and CTest (repsp and reDMP1).
4. The user plays the recorded song and listens to the key sounds and the mode select effects (the user's check).

## 5. Record

- `docs/analysis/audio.md`: the key-sound path (which SAS functions, how many voices, source format, pitch, ADSR and volume values), as facts about the original. Nothing about the user's files.
- **repsp**: the changed HLE behaviour and its basis.
- **Work log** `docs/work-logs/20261117-i041-key-sounds.md`: findings, measurement tables and questions.
