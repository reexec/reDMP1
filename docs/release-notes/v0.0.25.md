# reDMP1 v0.0.25

Screen shaders.

Issue [#49](https://github.com/reexec/reDMP1/issues/49).

- **Request** (user, 2026-11-18): bring over re2DJ's screen shader feature.
- **Menu**: the Graphics tab's Screen shader item chooses `none`, `crt`, `scanline`, `fsr`, `scalefx`, `anime4k`, or a `.glsl`/`.glslp` file in `shaders/` (the working directory's, otherwise beside the executable).
  - It has parameter sliders, a reset to defaults, Reload, and error display.
  - It is disabled without an OpenGL context.
- **Settings**: saved as `PostShader` in `redmp1.ini`. `--post-shader <id>` (or `=<id>`), then `REDMP1_POST_SHADER`, take precedence over the file and are not written to it. Parameter values are not saved.
- **Fixed during review**: the user found that `scalefx` and `anime4k` showed the opening movie upside down.
- The platform side is repsp v0.0.24 ([reexec/repsp#50](https://github.com/reexec/repsp/issues/50)).

Commits from `16f58da` on task branch `i049-screen-shaders`, squashed into this release's merge commit.

Measured (windowed):

- With `none`, input script to gameplay, three runs: mean present interval 20.30-20.47 ms, no unresolved-address dispatches, no crashes.
- All five built-ins run through at a 3x window.

Confirmed by the user.

Known limits: dialogs are not drawn on screen. Save data is plaintext.

Verified: Win64 Release (Visual Studio generator), Win64 Ninja Debug/Release and Linux x64 Debug/Release, build and CTest.
