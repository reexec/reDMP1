# reDMP1 v0.0.15

Lifter audit: a full check of end-of-body decisions, a run-time stack balance check, and the 64 MiB stack reservation removed.

Issue [#16](https://github.com/reexec/reDMP1/issues/16): the static checker `tools/lift_audit.py` (reads the relocated image and the generated code and compares, for every body, the kind of its last instruction with the shape of the generated ending); in the diagnostic build (`REDMP1_TRACE_GUEST=ON`), the lifter's stack balance hooks and per-guest-thread host stack high-water measurement; the generated-code target built optimized in every configuration (MSVC `/O2` without `/RTC1`; GCC `-O2`) and MSVC's 64 MiB `/STACK` reservation removed. Commits from `da06f6c` on task branch `i016-lifter-audit`, squashed into this release's merge commit.

Measured (**confirmed**):
* Static check: zero mismatches across all 8,785 generated bodies. On code lifted without patch 0003 it reports four `jalr` mismatches, one of them the site behind the v0.0.8 assertion (confirming the tool catches the known defect).
* Run-time check (opening to gameplay): zero stack imbalances at call sites and body exits. Positive imbalances reported inside bodies were judged false reports for bodies whose epilogue lies in another body. No new lifter patch was needed.
* Host stack high-water of the main guest thread: about 435 KiB in Release, 18.8 MiB in Debug, about 345 KiB in Debug with only the generated code optimized.
* Without the 64 MiB reservation, the scripted run to gameplay completed on Win64 Debug (Visual Studio generator) and Linux Debug/Release.

Known limits: MSVC does not guarantee tail-call optimization, so the stack measurement must be repeated when the generated code changes (the diagnostic build's summary shows it). Dialogs are not drawn on screen. Save data is plaintext. The ATRAC loop end point is unresolved.

Verified: Win64 (`scripts\build_win64.bat Release ffmpeg` CTest 35/35, `Debug` CTest passing) and Linux x64 (WSL Ubuntu 24.04, Debug/Release CTest 34/34, zero warnings including the diagnostic build).
