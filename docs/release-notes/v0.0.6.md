# reDMP1 v0.0.6

Audio wired in: past audio setup and the start of the sound threads, stopping at the first video call.

Issue [#11](https://github.com/reexec/reDMP1/issues/11): repsp's sceAudio, sceSasCore and sceAtrac3plus HLE registered in the app, audio statistics in the stop report; `--max-vblanks`, which ends a headless run after a given number of vblanks, with stop class (e); CTest `app_boot` updated to the new stop point; `docs/analysis/audio.md` (channel layout, SAS setup, sound threads); repsp pinned at v0.0.6 (`5a823a0`). Commits from `3cd55f2` on task branch `i011-audio`, squashed into this release's merge commit.

Measured (**confirmed**): four audio channels reserved (stereo; 448, 256, 256 and 256 samples), `__sceSasInit` (grain 256, 32 voices, 44100 Hz), two sound threads started at priority 18, then three PRX modules loaded (`videocodec.prx`, `mpegbase.prx`, `mpeg.prx`) and a stop at `sceMpeg` `sceMpegInit` (`0x682A619B`). No primitive is drawn yet. Three runs give the same HLE call order and arguments (only system-time return values differ).

Known limit: ATRAC3plus decodes to silence (user decision; the decoder is chosen when sound is needed).

Verified: build and CTest 29/29 (with game data) on Win64 Debug/Release and Linux x64 (WSL Ubuntu 24.04), and 23/23 in the configuration without game data.
