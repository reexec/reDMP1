# reDMP1 v0.0.5

Input wired in: past input setup to PRX loading and opening data files, stopping at the first audio call.

Issue [#9](https://github.com/reexec/reDMP1/issues/9): repsp's sceCtrl and sceDmac HLE registered in the app (keyboard and gamepad; neutral input when headless), ctrl statistics in the stop report; CTest `app_boot` updated to the new stop point; the progress after input setup recorded in `docs/analysis/first-frame.md`; the input mapping in the guide; repsp pinned at v0.0.5 (`19366ed`). Commits from `b40bfae` on task branch `i009-input`, squashed into this release's merge commit.

Measured (**confirmed**): after `sceCtrlSetSamplingMode(1)` (analog) and `sceCtrlSetSamplingCycle(0)` the game loads three PRX modules (`sc_sascore.prx`, `audiocodec.prx`, `libatrac3plus.prx`), opens two data files asynchronously and stops at `sceAudio` `sceAudioChReserve` (`0x5EC81C55`). No primitive is drawn yet; the one frame presented is black. Three runs give the same HLE call order and arguments (only system-time return values and vblank counts differ).

Verified: build and CTest 26/26 (with game data) on Win64 Debug/Release and Linux x64 (WSL Ubuntu 24.04), and 20/20 in the configuration without game data.
