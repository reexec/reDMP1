# reDMP1 v0.0.2

Lift & link: the module is relocated to `0x08804000` as the real firmware places it, the lifted code is linked, and it runs up to its first firmware call.

Issue [#3](https://github.com/reexec/reDMP1/issues/3): two local allegrexrecomp patches (`patches/psprecomp/`: `--base` relocation and the `relocate` subcommand, one analysis path with segment-based seed harvesting; not submitted upstream); `lift.json` (`0x08804000`); `reloc_check` and `lift_invariance` (local); the psprecomp ABI adapter `src/recomp_abi/` (28 symbols, dispatch and VFPU carried from psprecomp `5ca18fa` with attribution, stops through repsp's `repsp_raise_stop`); `redmp1_recomp`; `redmp1 roms --lift-check`; repsp pinned at v0.0.2 (`7e6ef68`); the executable analysis updated. Commits from `e9a2322` on task branch `i003-lift-and-link`, squashed into this release's merge commit.

Measured (**confirmed**): the 3,747,092-byte image with 37,010 relocations applied is identical from repsp, the patched allegrexrecomp and a separate reference; 8,785 functions, 92.0% `.text` coverage, identical at base 0 and `0x08804000` after the shift; the starts lost since issue #1 are only the import stubs, data decoded as code and unreferenced fragments. `--lift-check` stops at `ThreadManForUser:0x446D8DE6` (`sceKernelCreateThread`) called from `0x0880419C` (kernel HLE is the next task).

Verified: build and CTest 17/17 (with game data) on Win64 Debug/Release and Linux x64 (WSL Ubuntu 24.04).
