# reDMP1 v0.0.30

Autoplay.

Issue [#59](https://github.com/reexec/reDMP1/issues/59):

- **Request** (user, 2026-11-21): analyse the game so that autoplay can be toggled from the OSD.
- **Analysis** (`docs/design/20261121-i059-autoplay.md`):
  - the gameplay scene (vtable `0x088ED7A0`);
  - the judgement and score objects, and the chart time;
  - each channel's note array;
  - the buttons-to-lanes layout table (layouts 0/1/2);
  - long notes: type 1, with a length of 7 or more at `+14`, ending at time + length.
- **Approach**: on the frame a note reaches the judgement line, its lane's button reads as pressed, through repsp v0.0.29's button filter ([reexec/repsp#63](https://github.com/reexec/repsp/issues/63)).
  - Judgement, score and key sounds are the game's own, and high scores are saved as usual (user decision).
  - While autoplay runs, human lane buttons are cleared.
  - When pausing stops the chart clock, buttons pass unchanged, so the pause menu works.
- **Menu**: an Autoplay checkbox in the Input tab, an AUTOPLAY label at the top right while it is on, and `--autoplay`. Each run starts with it off.
- **Also**: each menu tab fits its own content, and table label columns fit their longest label.

Commits from `e7f3372` on task branch `i059-autoplay`, squashed into this release's merge commit.

Measured (windowed, one whole song on autoplay):

- STAGE CLEARED, MAX 149 / BREAK 0 / COMBO 149, 100.0%, S.
- No unresolved-address dispatches.

Confirmed by the user.

Known limits: dialogs are not drawn on screen. Save data is plaintext.

Verified: Win64 Release (Visual Studio generator), Win64 Ninja Debug/Release and Linux x64 Debug/Release, build and CTest.
