# reDMP1 v0.0.31

Move to psprecomp upstream v0.6.0.

Issue [#62](https://github.com/reexec/reDMP1/issues/62): the submodule moves to upstream psprecomp v0.6.0 (`14749c1`) (`docs/design/20261121-i062-psprecomp-v060.md`).

- **Patches**:
  - Local patches 0001 (#36), 0003 (#31), 0004 (#35) and 0006 (#38) are now upstream and are deleted.
  - The remaining 0005 (`--trampoline`) is regenerated from [sp00nznet/psprecomp#37](https://github.com/sp00nznet/psprecomp/pull/37), rebased onto v0.6.0.
- **ABI adapter**:
  - In v0.6.0, runtime functions own a guest call's return-site frame, not the emitted body (#32). So `psp_call_guest_fn` and `psp_call_guest_addr` are added.
  - They run the callee and the tail chain it leaves, and clear an unwind aimed at their own return site.
  - The probe covers them.
- **Regenerated code**: only the call form at 12,042 guest call sites and the header's call macros change.

Commits from `a11f268` on task branch `i062-psprecomp-v060`, squashed into this release's merge commit.

Measured:

- Release, one song on autoplay: STAGE CLEARED, MAX 149 / BREAK 0, 100%, S. No unresolved-address dispatches.
- Debug (generated code unoptimized), the same song: runs to the end with no stack overflow.
- FPS: the same as v0.0.30 (mean frame interval 18.92 ms).
- Confirmed by the user.

Known limits: dialogs are not drawn on screen. Save data is plaintext.

Verified: Win64 Release (Visual Studio generator), Win64 Ninja Debug/Release and Linux x64 Debug/Release, build and CTest.
