# reDMP1 v0.0.23

One noise frame at the jacket-to-gameplay transition, and song-select preview stutter.

Issue [#44](https://github.com/reexec/reDMP1/issues/44).

- **Report** (user, 2026-11-18): one frame of noise at the transition from the song jacket to gameplay, absent on the real hardware and another emulator.
- **Ruled out**, one by one: draw-state interpretation, memory allocation, displayed-buffer switching and execution order.
- **Cause**: the game passes uncached addresses for the list and the stall, while jumps inside the list go to bus addresses. The GE missed the stall and ran stale jacket commands from an earlier frame.
- **Second defect, found by the user during the fix**: v0.0.22's texture hashing walked whole textures byte by byte on every draw, so song-select preview streaming stuttered. The cause was found by comparing four repsp revisions.
- **Fix**: repsp v0.0.22 fixes both ([reexec/repsp#45](https://github.com/reexec/repsp/issues/45), [#46](https://github.com/reexec/repsp/issues/46)).

Commits from `dfe46b5` on task branch `i044-transition-noise`, squashed into this release's merge commit.

Measured (**confirmed**, windowed):

- No noise frame at the transition in a two-song run, with either renderer (sw and gl).
- During the song-select preview, music channel underruns went from 1,981 to 68.
- The presentation interval went from 27.4 ms to 19.8 ms.

Confirmed by the user. The **unconfirmed** item in `docs/analysis/scene-flow.md` now states the cause.

Known limits: dialogs are not drawn on screen. Save data is plaintext.

Verified: Win64 Debug/Release (Visual Studio generator) and Linux x64 Debug/Release, build and CTest.
