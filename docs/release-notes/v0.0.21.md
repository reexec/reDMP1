# reDMP1 v0.0.21

Key sounds: clicks and noise removed.

Issue [#41](https://github.com/reexec/reDMP1/issues/41).

- **Report** (user, 2026-11-17): key sounds did not sound right during play.
- **Recording comparison**: the music was the same in both recordings. Only reDMP1 had broadband noise and large steps (clicks) at key-sound moments.
- **Ruled out**: the key-sound path (SAS, channel 2) matched the specification in its calls, source VAG and synthesis.
- **Cause**: presenting a frame held the guest CPU while waiting for the host's vertical sync. The effect thread woke late and its short channel queue ran dry.
- **Fix**: repsp v0.0.20 ([reexec/repsp#41](https://github.com/reexec/repsp/issues/41)).

Commits from `95777ed` on task branch `i041-key-sounds`, squashed into this release's merge commit.

Measured (**confirmed**, windowed, with a lane-input script during play):

| | Before | After |
|---|---|---|
| Gameplay effect-channel underruns | 474 | 9-14 |
| Effect-thread wakes 10 ms or more late | 25-180 | 2-3 |

There were zero undiscovered-address dispatches and zero crashes. The user replayed the recorded song and confirmed the key sounds are right. Facts about the key-sound path are in `docs/analysis/audio.md`.

Known limits: dialogs are not drawn on screen. Save data is plaintext.

Verified: Win64 Debug/Release (Visual Studio generator) and Linux x64 Debug/Release, build and CTest.
