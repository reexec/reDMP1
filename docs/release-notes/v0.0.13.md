측정(**확인됨**): 게임은 한 번만 나는 효과음도 모두 loop 인자를 켜서 건다. 효과음 데이터의 끝 블록에는 끝 플래그만 있고 반복 플래그가 없다. 모드 선택의 배경 음악은 좌우 두 음성으로 나는 SAS 음원이고, 블록마다 반복 플래그가 있어 실제로 반복한다. 타이틀·곡 선택·플레이의 배경 음악은 ATRAC3plus 스트림이다.

사용자 확인(2026-11-15, 창 모드): 효과음의 반복은 사라졌다. 소프트웨어 렌더러에서는 소리가 전체적으로 끊기고 모드 선택의 음악이 느리게 들린다. OpenGL 렌더러에서는 끊김과 느려짐이 대부분 사라진다.

알려진 한계(다음 과제): 위의 끊김과 느려짐. 원인은 화면 그리기가 게임 스레드 위에서 끝까지 실행되어 소리를 섞는 스레드가 그동안 돌지 못하는 것이다(녹화의 소리가 약 20 ms 소리, 10 ms 무음의 반복이었다). OpenGL에서 남는 끊김의 원인은 아직 모른다. ATRAC 스트림의 루프 끝 지점이 비정상 값으로 읽힌다(미해결).

검증: Win64(`scripts\build_win64.bat Release ffmpeg`, CTest 35/35)와 Linux x64(WSL Ubuntu 24.04, CTest 34/34).

# reDMP1 v0.0.13

Sound defects: sound effects that kept repeating are fixed.

Issue [#26](https://github.com/reexec/reDMP1/issues/26): the cause of the repeating sound effects confirmed and fixed (the SAS fix in repsp v0.0.13); an inventory of sounds in `docs/analysis/audio.md` (screen, path, source format, output channel); the audio diagnostics in `docs/guides/running-and-tracing.md`; repsp pinned at v0.0.13 (`a400679`). Commits from `d3c7e91` on task branch `i026-sound-defects`, squashed into this release's merge commit.

Measured (**confirmed**): the game sets the loop argument even for one-shot sound effects, whose data ends in a block with the end flag and no repeat flag. The mode select background music is a SAS source played as two voices, left and right, with the repeat flag on every block, and it really loops. Background music on the title, song select and gameplay screens is ATRAC3plus streams.

User check (2026-11-15, windowed): sound effects no longer repeat. With the software renderer all sound has gaps and the mode select music seems slow; with the OpenGL renderer the gaps and the slowness are mostly gone.

Known limits (the next task): those gaps and that slowness. The cause is that drawing runs to completion on a game thread, so the thread that mixes sound cannot run meanwhile (the recording's audio was a repeating pattern of about 20 ms of sound and 10 ms of silence). What causes the gaps that remain with OpenGL is not yet known. The loop end point of ATRAC streams reads as an abnormal value (unresolved).

Verified: Win64 (`scripts\build_win64.bat Release ffmpeg`, CTest 35/35) and Linux x64 (WSL Ubuntu 24.04, CTest 34/34).
