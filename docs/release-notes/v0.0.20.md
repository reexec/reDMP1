# reDMP1 v0.0.20

Reducing the stack safety nets after the trampoline.

Issue [#39](https://github.com/reexec/reDMP1/issues/39): by the user's decision (2026-11-17), two safety nets were reduced.

- repsp is now v0.0.18, so the default host stack reservation for guest threads drops from 64 MiB to 8 MiB ([reexec/repsp#37](https://github.com/reexec/repsp/issues/37)).
- The forced optimization of the generated code in Debug is gone, together with the measurement option `REDMP1_RECOMP_UNOPT`. Debug now builds the generated code with standard Debug flags (`/Od /RTC1`, `-O0 -g`).
- Trampoline patch 0005 was submitted upstream ([sp00nznet/psprecomp#37](https://github.com/sp00nznet/psprecomp/pull/37)).

Commits from `c141788` on task branch `i039-stack-safety-nets`, squashed into this release's merge commit.

Measured (**confirmed**) with standard Debug (generated code unoptimized), running 3,600 vblanks at gameplay. Guest thread host stack high-water was 28 KiB for `user_main` and 12-16 KiB for the rest, about 0.3% of the 8 MiB reservation. Three Release runs to gameplay had zero undiscovered-address dispatches and zero crashes. The user played one song to the end in windowed mode.

Known limits: key sounds do not sound as they should (to be investigated). Dialogs are not drawn on screen. Save data is plaintext.

Verified: Win64 Debug/Release (Visual Studio generator) and Linux x64 Debug/Release, build and CTest.
