# reDMP1 v0.0.3

Boot: from `module_start` on the kernel HLE to the first non-kernel firmware call.

Issue [#5](https://github.com/reexec/reDMP1/issues/5): the app's default run (`redmp1 <game_dir>`) with `KernelConfig` (`disc0:`/`umd0:` on the game directory, `ms0:` on a user folder), the module image reserved, the `module_start` thread (`lift.json` `start_thread`: priority `0x20`, stack `0x40000`), stop classes and exit codes, and a trace summary; CTest `app_boot` (local); `docs/analysis/boot.md` (the boot sequence) and the import name/NID table; repsp pinned at v0.0.3 (`c9c2a5e`). Commits from `3359c8c` on task branch `i005-boot`, squashed into this release's merge commit.

Measured (**confirmed**): `module_start` → `user_main` (priority `0x20`, 128 KiB stack) → memory manager setup (a 19 MiB user heap) → stop at the first non-kernel call, `sceGe_user` `sceGeSetCallback` (`0xA4FC06A4`); no file is opened before it, and three runs give the same HLE trace.

Verified: build and CTest 21/21 (with game data) on Win64 Debug/Release and Linux x64 (WSL Ubuntu 24.04).
