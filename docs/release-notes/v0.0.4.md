# reDMP1 v0.0.4

GE and display wired in: the GE setup lists run, the frame buffer is set, and the boot reaches the next unimplemented call.

Issue [#7](https://github.com/reexec/reDMP1/issues/7): repsp's GE and display HLE registered in the app, a window (2x) and `--headless`, `REPSP_FRAME_DUMP`, GE and display statistics in the stop report; `get_fpr`/`set_fpr` in the adapter; NID names from repsp's SHA-1 table (the app's hand-written table removed); CTest `app_boot` also matching the stop NID's name; `docs/analysis/first-frame.md` (the GE setup sequence, the command table, the frame buffers); repsp pinned at v0.0.4 (`1af10f7`). Commits from `23bc102` on task branch `i007-first-frame`, squashed into this release's merge commit.

Measured (**confirmed**): after `sceGeSetCallback` the game runs two GE lists (282 commands, state setup only, nothing drawn), calls `sceDisplaySetMode(0, 480, 272)` and `sceDisplaySetFrameBuf(0x04044000, 512, 5551, next vblank)`, and stops at `sceCtrl` `sceCtrlSetSamplingMode` (`0x1F4011E6`). It double-buffers (the draw buffer is at VRAM `0x04000000`). The game stops before its first draw, so there is no picture yet. Three runs give the same HLE trace.

Verified: build and CTest 23/23 (with game data) on Win64 Debug/Release and Linux x64 (WSL Ubuntu 24.04).
