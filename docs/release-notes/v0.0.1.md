# reDMP1 v0.0.1

The first release: the bootstrap of the static recompilation project for DJMAX Portable (Korea build `ULKS-46050`, 1.02).

Issue [#1](https://github.com/reexec/reDMP1/issues/1): the rules (as reCT3's), the charter, the design and work order with review 1; the submodules `third_party/repsp` (v0.0.1, `730c404`) and `third_party/psprecomp` (`5ca18fa`); the Win64 and Linux x64 build skeleton with the `allegrexrecomp` host tool; the title layer (profile, `variants.json`, variant lookup) and the `redmp1` app (disc identification by `DISC_ID`, `DISC_VERSION` and the `BOOT.BIN` SHA-1); `register_disc.py`, `regenerate.py`, `lifter.py`; analysis of the original disc and executable (`docs/analysis/`); CTest for the app smoke checks and the repsp probes; CI (Win64 Debug/Release, Linux x64 Debug/Release, Linux apt through the Kakao mirror) and the release workflow. Commits `8cdd91f`…`323a87f` on task branch `i001-project-bootstrap`, squashed into this release's merge commit.

Executable analysis (**confirmed**, measured with `allegrexrecomp`): `BOOT.BIN` is the plain relocatable PRX `djmax` with 9,159 functions, 92.4% `.text` coverage, 212 jump tables (none unresolved) and 159 imported functions from 20 libraries. That `BOOT.BIN` and `EBOOT.BIN` hold identical bytes is **inferred** (their header values match).

Verified: build and CTest 11/11 (10/10 without game data) on Win64 Debug/Release (Visual Studio 17 2022, x64) and Linux x64 Debug/Release (WSL Ubuntu 24.04).
