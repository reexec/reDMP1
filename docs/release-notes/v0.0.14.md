# reDMP1 v0.0.14

Audio gaps fixed; OpenGL becomes the default renderer.

Issue [#28](https://github.com/reexec/reDMP1/issues/28): the default renderer in windowed mode is now OpenGL (when no GL context can be created the reason is stated and software is used; the default under `--headless` stays software); `--audio-latency-ms <n>` (default 20); audio statistics and a wake latency summary (`REPSP_SCHED_STATS=1`) in the stop report; the measuring tool `tools/audio_gaps.py`; the sound thread structure in `docs/analysis/audio.md`; repsp pinned at v0.0.14 (`e3beb45`). Commits from `af7c3e8` on task branch `i028-audio-gaps`, squashed into this release's merge commit.

Measured (title to gameplay, 2100 vblanks): before the fixes the software renderer's device output had 42 "short silences with sound on both sides" headless and 117 windowed, and the sound thread waited more than 10 ms after waking about 650 times with software and about 230 times with OpenGL. With preemption points during drawing those counts fell to 14-52 and 3, and with the host-side buffer OpenGL (windowed) has zero short silences. The software renderer still has 17 headless and 34 windowed.

User check (2026-11-15, windowed): it is better.

Known limits: the software renderer's gaps are fewer but remain. Sound has a gap during loading between screens (stretches where game code runs long without a system call; measured only). Sound is delayed by the intermediate buffer (20 ms by default). The loop end point of ATRAC streams reads as an abnormal value (unresolved). Dialogs are not drawn on screen. Save data is plaintext. Judgement during play and the result screen have not been checked yet.

Verified: Win64 (`scripts\build_win64.bat Release ffmpeg`, CTest 35/35) and Linux x64 (WSL Ubuntu 24.04, CTest 34/34).
