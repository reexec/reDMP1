# reDMP1 v0.0.26

Background music heard later than the notes, and a music offset setting.

- **Issue [#51](https://github.com/reexec/reDMP1/issues/51)**:
  - **Report** (user, 2026-11-19): the background music is later than the notes.
  - The last audio change (v0.0.21) was not the cause: builds before and after it give the same music statistics.
  - repsp v0.0.25 fixes four causes: the blocking output's return threshold, the ATRAC encoder delay, the GL lock wait, and a start offset API.
  - **Music offset**: for the remaining gap, the new **Audio** tab has "Music offset (ms)" (−300 to +300 in steps of 5). Positive starts the music earlier, negative later, from the next track. It is saved as `MusicOffsetMs` in `redmp1.ini` (default 0).
  - Commits from `ae3f44c` on task branch `i051-music-latency`, squashed into this release's merge commit.
- **Issue [#52](https://github.com/reexec/reDMP1/issues/52)**:
  - **Cause**: recompiled code handed over the guest CPU only at HLE calls, so a long computation without one held back a higher-priority thread whose timer had expired (a sound thread ran up to 1000 ms late).
  - **Fix**: local psprecomp patch `0006` lets `PSP_LOOP`, on every backward branch, call `psp_loop_hook`. reDMP1 checks the scheduler once every 1024 calls.
  - Not yet submitted upstream.
  - **Regenerate the generated code** (`scripts/recomp/regenerate.py`). The patched `allegrexrecomp` must be the most recently built one; otherwise name it with `ALLEGREXRECOMP`.
  - Commit `89e44b0` on task branch `i051-music-latency`, squashed into this release's merge commit.

Measured (windowed, input script to gameplay, three runs):

- No unresolved-address dispatches, no crashes, no mid-song underruns.
- The latest thread resume was 6.7 ms late, against up to 1000 ms before.
- Mean present interval 18.9 ms.

The user tuned the offset and confirmed.

Still to do: analyse the remaining delay so that no offset is needed. Of about 100 ms, the host path accounts for 45-70 ms; the rest is unexplained.

Known limits: dialogs are not drawn on screen. Save data is plaintext.

Verified: Win64 Release (Visual Studio generator), Win64 Ninja Debug/Release and Linux x64 Debug/Release, build and CTest.
