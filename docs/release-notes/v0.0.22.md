# reDMP1 v0.0.22

Song jacket: the previous song's jacket from the second song on.

Issue [#43](https://github.com/reexec/reDMP1/issues/43).

- **Report** (user, 2026-11-17): starting a second song showed the first song's jacket. It was right with the software renderer and wrong only with OpenGL.
- **Cause**: the OpenGL texture cache always hashed texture contents in user RAM to 0. A new jacket at the same address therefore kept the old texture.
- **Fix**: repsp v0.0.21 ([reexec/repsp#43](https://github.com/reexec/repsp/issues/43)).

Commits from `0bc0fee` on task branch `i043-song-jacket`, squashed into this release's merge commit.

Measured (**confirmed**):

- Screen dumps of a two-song run show the right jacket for each song.
- Three runs to gameplay had zero undiscovered-address dispatches and zero crashes, with presentation intervals in the same range as before.
- The user picked two songs in a row and confirmed.

Known limits:

- The fix uncovered something it had hidden: one frame of noise at the jacket-to-gameplay transition, which the real hardware and another emulator do not show ([#44](https://github.com/reexec/reDMP1/issues/44), to be investigated).
- Dialogs are not drawn on screen.
- Save data is plaintext.

Verified: Win64 Release (FFmpeg) and Debug, and Linux x64 Debug/Release, build and CTest.
